**틀린 내용(❌)은 없었습니다.** 아래는 **정답으로 기억할 것**입니다. 노트에는 이미 ⚠️ 상자로 반영했으니 따로 고칠 필요는 없습니다. 원래 문장은 기록용으로 남겼고, 복습할 때는 ⚠️ 상자 내용이 정답입니다.

- **09-2 ⚠️ 가장 중요** RAGAS의 Context Precision은 단순한 `TP / (TP + FP)`가 아니라 **순위를 반영한 평균 정밀도**다. 관련 문서가 **위에 있을수록** 점수가 높다. 노트 예시처럼 5개 중 3개가 관련 있어도, 그 3개가 1~3위면 **1.0**, 3~5위면 약 **0.48**이 나온다
- **09-9 ⚠️** RAGAS의 Answer(Response) Relevancy는 **임베딩 코사인 유사도만** 쓴다. Cross-Encoder로 재는 방식은 RAGAS 기본 지표에 없다
- **10-9 ⚠️** 실습의 `LangchainLLMWrapper`는 설치된 ragas 0.4.4에서 **곧 없어질(deprecated) 클래스**라는 경고가 뜬다. 대신 `llm_factory`를 쓰라고 안내한다
- **10-12 ⚠️** 실습 맨 위의 vertexai 더미 모듈은 설치된 ragas 0.4.4 기준으로는 **필요 없어 보인다**(라이브러리가 스스로 try/except로 처리함, 실행 확인은 안 함)

## 09. RAG 평가 지표

| # | 노트 내용 | 판정 | 출처 기준 내용 | 출처 |
|:-:|---|:-:|---|---|
| 09-1 | TP·FP·FN 정의, 정밀도 = TP/(TP+FP), 재현율 = TP/(TP+FN) | ✅ | 정보 검색·분류에서 쓰는 표준 정의와 같다 | [Wikipedia: Precision and recall](https://en.wikipedia.org/wiki/Precision_and_recall) |
| 09-2 | Context Precision = TP/(TP+FP). 예: 5개 중 3개 관련 → 3/5 | ⚠️ | 일반 정밀도 정의로는 맞지만, **RAGAS의 Context Precision은 다르다**. "관련 청크를 관련 없는 청크보다 **위에 두는 능력**"을 재고, 관련 청크 위치마다 precision@k를 구해 평균 낸다. 설치된 소스도 `numerator += cumsum / (i + 1)` 후 관련 개수로 나눈다. 그래서 같은 3/5라도 순서에 따라 1.0 ~ 약 0.48로 달라진다 | `ragas/metrics/_context_precision.py` 113–132행, [RAGAS Docs: Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/) |
| 09-3 | Context Recall = TP/(TP+FN). (Claude 보충) RAGAS는 문장 단위로 확인 | ✅ | 모범 정답의 각 문장이 검색된 문서로 뒷받침되는지(1/0) 분류하고, `뒷받침된 문장 수 / 전체 문장 수`로 계산한다 | `ragas/metrics/_context_recall.py` 49·114–117행 |
| 09-4 | 정밀도와 재현율은 반비례하는 경향이 있다 | ✅ | "**자주(Often)** 반비례 관계가 있어서 하나를 올리면 다른 하나가 떨어진다. 상황에 따라 어느 쪽을 중시할지 정한다." 예: 화재경보기는 놓치면 큰일이라 오경보를 감수한다 | [Wikipedia: Precision and recall](https://en.wikipedia.org/wiki/Precision_and_recall) |
| 09-5 | F1 = 조화평균, 한쪽이 낮으면 크게 낮아진다 | ✅ | F1은 정밀도와 재현율의 조화평균이다. 조화평균은 낮은 쪽 값에 더 큰 영향을 받는다 | [Wikipedia: F-score](https://en.wikipedia.org/wiki/F-score) |
| 09-6 | Faithfulness: 답변을 개념 문장으로 쪼개 컨텍스트에서 확인, 낮으면 환각 | ✅ | 답변에서 뽑은 주장(statement)마다 컨텍스트로 뒷받침되는지 판정하고 `근거 있는 주장 수 / 전체 주장 수`로 계산한다 | `ragas/metrics/_faithfulness.py` 182–192행 |
| 09-7 | Faithfulness가 낮으면 ① 프롬프트 개선 → ② 그래도 안 되면 모델 교체 | ❓ | 수업에서 배운 대처 순서로, 공식 문서에서 이 순서를 찾지 못했다 | — |
| 09-8 | Answer Relevancy: 답변에서 역질문을 만들어 원래 질문과 비교 | ✅ | LLM이 답변에서 질문을 기본 **3개**(`strictness=3`) 만들고, 원래 질문과의 코사인 유사도 평균을 낸다. 답변이 "모르겠다"처럼 회피(noncommittal)하면 **0점** | `ragas/metrics/_answer_relevance.py` 38·94·114–127행, [RAGAS Docs: Response Relevancy](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/) |
| 09-9 | 임베딩 거리 → Bi-Encoder, 정밀하게는 Cross-Encoder로 측정 | ⚠️ | RAGAS의 ResponseRelevancy는 **임베딩 코사인만** 쓴다(`MetricWithEmbeddings`). Cross-Encoder로 재는 옵션은 기본 지표에 없다. Cross-Encoder 방식은 직접 만들어 쓸 수는 있는 별도 아이디어다 | `ragas/metrics/_answer_relevance.py` 64·126행 |
| 09-10 | 관련성이 낮으면 노이즈 → 청킹·top-k 수정 | ❓ | 수업의 대처 요령. 공식 근거는 찾지 못했다. RAGAS 문서는 이 지표가 "사실 정확도가 아니라 질문 의도와의 일치"를 보며, **불완전하거나 군더더기가 있는 답**에 감점한다고 설명한다 | [RAGAS Docs: Response Relevancy](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/) |
| 09-11 | 4대 지표: Context Precision · Context Recall · Faithfulness · Answer Relevancy | ✅ | 네 지표 모두 RAGAS에 클래스로 있다 | `ragas/metrics/__init__.py` |

## 10. 골든셋과 RAGAS

| # | 노트 내용 | 판정 | 출처 기준 내용 | 출처 |
|:-:|---|:-:|---|---|
| 10-1 | 골든셋 = 질문·모범 정답·근거 문서, RAGAS 필드명 `user_input`·`reference`·`retrieved_contexts` (+`response`) | ✅ | `SingleTurnSample`의 필드 이름이 정확히 같다 | `ragas/dataset_schema.py` 60–75행 |

| 10-3 | 문서 외 함정 질문으로 환각을 확인한다 | ❓ | 좋은 실무 방법이지만, RAGAS 공식 질문 유형에는 없다 | — |

| 10-5 | (Claude 보충) `06_01`의 필드 이름 `retrived_contesxts`는 오타 | ✅ | RAGAS가 기대하는 이름은 `retrieved_contexts`다 | `ragas/dataset_schema.py` 62행, `chapter06_07/06_01.ipynb` |
| 10-6 | `EvaluationDataset.from_pandas` → `evaluate` → `to_pandas` | ✅ | `from_pandas` 클래스 메서드가 있다 | `ragas/dataset_schema.py` 251행 |
| 10-7 | ResponseRelevancy는 LLM + 임베딩이 필요 | ✅ | `MetricWithLLM`과 `MetricWithEmbeddings`를 모두 상속한다 | `ragas/metrics/_answer_relevance.py` 64행 |

| 10-9 | `LangchainLLMWrapper`로 LangChain 모델을 감싸 평가에 쓴다 | ⚠️ | 동작은 맞지만, 설치된 0.4.4에서 **"deprecated, 다음 버전에서 제거"** 경고를 내고 `llm_factory`를 쓰라고 안내한다 | `ragas/llms/base.py` 170행 |
| 10-10 | (Claude 보충) `bypass_temperature=True`는 RAGAS가 temperature를 덮어쓰지 않게 한다 | ✅ | 소스 주석: "일부 LLM(예: o1 계열)은 temperature를 지원하지 않는다". 이 옵션이 꺼져 있으면 RAGAS가 temperature를 **0.01(또는 0.3)으로 바꿔서** 호출한다. OpenAI 문서도 최신 추론 모델은 reasoning effort가 none이 아니면 temperature를 빼라고 한다 | `ragas/llms/base.py` 83–85·184–185·303행, [OpenAI Docs: Using the latest model](https://developers.openai.com/api/docs/guides/latest-model) |
| 10-11 | (Claude 보충) `temperature`는 무작위성, `reasoning_effort`는 생각하는 깊이 | ✅ | reasoning effort 값은 none ~ max 단계이고, 모델마다 지원 값이 다르다 | [OpenAI Docs: Using the latest model](https://developers.openai.com/api/docs/guides/latest-model) |
| 10-12 | vertexai 모듈이 없어서 가짜 모듈을 등록해 우회 | ⚠️ | 설치된 ragas 0.4.4는 vertexai import를 **try/except로 감싸** 없으면 `None`으로 둔다. 그래서 지금 버전에서는 더미 등록이 **필요 없어 보인다**. 실습 당시 다른 버전이었을 수 있고, 다시 실행해 확인하지는 않았다 | `ragas/llms/base.py` 24–36행 |
