## A. 꼭 공부할 것 (복습노트에 빠진 것)

### 01 · LLM의 한계와 RAG

- [ ] **인덱싱 단계 vs 질의 단계**
  - 인덱싱 = 질문이 오기 **전에** 미리 하는 일: 수집 → 분할 → 임베딩 → 저장
  - 질의 = 질문이 **오면** 실시간으로 하는 일: 검색 → 생성
  - 교안: [1장 2강](../lecture/ch01/102.md)
- [ ] **5단계별 병목 진단표**: 답이 틀렸을 때 어느 단계 문제인지 찾기
  - 수집: 스캔본·표 깨짐 / 분할: 문맥 단절 / 임베딩: 도메인 용어를 못 알아봄 / 검색: k 부족 / 생성: 지시 불이행·환각
  - 교안: [1장 2강](../lecture/ch01/102.md) (퀴즈 Q3: "근거를 무시하면 생성 단계 문제")

### 03 · ETL과 청킹

- [ ] **의미론적 분할 (Semantic Chunking)**
  - 원리: 옆 문장끼리 코사인 유사도를 재다가, 임계값 아래로 떨어지는 지점(breakpoint)에서 자른다
  - 장점은 청크 응집도↑, 단점은 임베딩 호출이 많아 비용·지연↑
  - 주의: 2장 3강은 `separators=["\n\n","\n","."," "]`로 문단·문장 경계부터 자르는 것도 이 이름으로 부른다. 1장 5강의 임베딩 기반 방식과 구분할 것
  - 교안: [1장 5강](../lecture/ch01/105.md), [2장 3강](../lecture/ch02/203.md)

### 04 · 벡터 저장소 (PGVector)

- [ ] **사전 필터링 (Pre-filtering) vs 사후 필터링 (Post-filtering)**
  - 사전: 거리를 계산하기 **전에** 메타데이터 조건으로 후보를 줄인다 → 속도와 정확도가 같이 좋아진다
  - 사후: 먼저 검색한 **뒤에** 조건으로 거른다
  - 필터 딕셔너리에 키를 여러 개 쓰면 **AND 조건**이 된다
  - 교안: [1장 6강](../lecture/ch01/106.md) (퀴즈 Q3), [3장 4강](../lecture/ch03/304.md)
- [ ] **메타데이터 3분류와 스키마 설계**
  - 식별(source, doc_id, author) / 시간(created_at, year) / 구조(section, page, chunk_id)
  - 필드마다 자료형을 정한다. 예: year는 **정수**여야 `$gte` 같은 비교 필터가 된다
  - 메타데이터는 DB의 `cmetadata` 컬럼(JSONB)에 저장된다
  - 메타데이터가 필요한 이유 3가지: 시간적 유효성, 출처 추적성, 검색 연산 비용 절감
  - 교안: [1장 6강](../lecture/ch01/106.md), [2장 6강](../lecture/ch02/206.md)

### 05 · 리트리버와 RAG 체인

- [ ] **출처 표기와 응답 후처리**: 3장 7강 전체
  - 검색된 원본 Document를 `source_documents`로 따로 보관하는 분기 패턴
  - 답변과 출처를 나눠서 보여 주는 후처리
  - `metadata.get("키", 기본값)`으로 출처 출력하기
  - 교안: [3장 7강](../lecture/ch03/307.md)
- [ ] **거리 점수 해석**
  - 거리 구간: 0~0.35 우수 / 0.35~0.60 보통 / 0.60 초과 주의(노이즈)
  - 저장소에 없는 질문을 넣어도 결과는 **비지 않는다**. 가장 덜 먼 문서 k개가 그대로 나오고 거리만 0.9대로 커진다
  - 검색 실패 점검 3가지: 1위 거리가 0.6 이상이면 문서가 있는지 확인 / 청크가 너무 길어 주제가 섞였는지 / 동음이의어로 질문이 엉뚱하게 임베딩됐는지
  - 교안: [3장 2강](../lecture/ch03/302.md) (퀴즈 Q3)
- [ ] **Top-k 정하기와 임계값 분기**
  - k가 크면 노이즈·토큰 비용↑, 작으면 근거가 빠져 환각↑
  - 시작값: 단답형 k=2~3, 종합형 k=4~6
  - `score <= 0.60`으로 직접 거른 뒤, 통과한 문서가 0건이면 **LLM을 부르지 않고** "찾을 수 없습니다"를 돌려준다
  - 교안: [3장 3강](../lecture/ch03/303.md)

### 06 · BM25와 하이브리드 검색

- [ ] **질의 유형 3가지와 유형별 가중치**
  - 유형: 고유명사·단순 키워드형 / 의미 탐색형 / 복합 조건형
  - 추천 가중치(BM25 : 벡터): 고유명사·약어는 0.8:0.2, 균형은 0.5:0.5, 의도·서술형은 0.2:0.8
  - 교안: [5장 3강](../lecture/ch05/503.md) (퀴즈 Q2), [5장 6강](../lecture/ch05/506.md)
- [ ] **어휘 불일치 (Vocabulary Mismatch)와 벡터 검색이 실패하는 경우**
  - 어휘 불일치: 질문 단어와 문서 단어가 달라서 키워드 검색이 못 찾는 문제
  - 벡터 검색은 희귀한 코드(ERR_902, 제14조 제2항)를 평균적인 의미로 뭉개서 놓친다
  - 같은 질문의 BM25 결과와 벡터 결과를 LLM에 넘겨 실패 원인 리포트 만드는 실습
  - 교안: [5장 6강](../lecture/ch05/506.md) (퀴즈 Q2)

### 08 · 쿼리 변환

- [ ] **Memory 기반 검색 (맥락 복원)**: 교안의 쿼리 변환 4기법 중 넷째
  - 이전 대화를 보고 "그거" 같은 대명사를 채워서, 혼자서도 검색되는 질문으로 다시 쓴다
  - 교안의 4기법은 Query Rewrite, HyDE, Query Routing, Memory 기반 검색이다
  - 교안: [4장 4강](../lecture/ch04/404.md) (퀴즈 Q2)
- [ ] **BM25 ↔ 벡터 자동 라우팅**
  - LLM 라우터가 `bm25` 또는 `vector`를 출력하면 if문으로 해당 검색기를 고른다
  - 질의 유형 → 최적 전략 매핑 표, 라우팅 전후 비교로 개선 확인
  - 교안: [5장 7강](../lecture/ch05/507.md)

### 09 · RAG 평가 지표

- [ ] **검색 실패 vs 생성 실패 구분과 진단 순서**
  - 순서: 근거 문서를 제대로 가져왔나 → Faithfulness → Answer Relevance
  - 환각 두 종류: 외부 지식이 섞임 / 논리 왜곡(조건 A와 B를 섞어 잘못 연결)
  - 교안: [6장 2강](../lecture/ch06/602.md)

### 10 · RAG 평가: 골든셋과 RAGAS

- [ ] **생성 실패 3대 원인과 해결책**
  - 환각 → Grounding 프롬프트
  - 문맥 무시 → 문맥 압축, 문서를 질문 바로 위로 옮김 (Lost in the Middle과 연결)
  - 지시 불이행 → 지시사항에 번호 매기기, Few-shot 예시
  - 실습: faithfulness 또는 answer_relevancy가 0.8 미만인 건을 골라 LLM으로 진단하고 CSV로 저장
  - 교안: [7장 6강](../lecture/ch07/706.md)
- [ ] **회귀 검증 흐름**
  - Baseline 프롬프트와 Improved 프롬프트를 **같은 평가셋**으로 비교한다
  - 부작용 방어: 새 규칙 때문에 정상 질문까지 답을 거부하지 않는지 확인
  - 결과 해석: 친절한 군더더기 문장도 근거 없는 주장으로 잡혀서, 개선 후 Faithfulness가 0.33 → 1.0으로 올랐다
  - 교안: [7장 7강](../lecture/ch07/707.md)
- [ ] **평가셋 품질 검수**
  - `isnull().sum()`과 `assert`로 결측치를 점검한다
  - LLM 검수관이 "모범 정답이 근거 문서와 맞는가"를 일치/불일치로 판정한다
  - 평가·채점 때는 temperature=0으로 고정한다
  - 골든셋에 근거 문서를 꼭 넣는 이유: 검색 실패와 생성 실패를 구분하는 기준선이라서
  - 교안: [7장 1강](../lecture/ch07/701.md) (퀴즈 Q1), [7장 2강](../lecture/ch07/702.md)

## B. 보충할 것 (복습노트에 얕게만 있는 것)

### 01 · LLM의 한계와 RAG

- [ ] **파인튜닝 vs RAG, 언제 무엇을 쓰나**
  - 파인튜닝: 말투·문체·페르소나, 엄격한 출력 형식(JSON)
  - RAG: 자주 바뀌는 지식(규정·가격표), 근거 링크가 필요할 때
  - 교안: [1장 1강](../lecture/ch01/101.md)

### 02 · 임베딩과 유사도

- [ ] **임베딩 모델 비교와 선택 기준**
  - text-embedding-3-small: 1,536차원, 범용·저비용
  - text-embedding-3-large: 3,072차원, 법률·의료 같은 고정밀
  - bge-m3: 1,024차원, 오픈소스, 로컬 보안·다국어
  - 선택 기준 3가지: 도메인 적합성, 인프라 비용(차원이 클수록 저장·연산 비용↑), 한국어·다국어 검증
  - 교안: [1장 3강](../lecture/ch01/103.md)
- [ ] **`embed_query` vs `embed_documents`**
  - `embed_query`: 질문 하나 → 벡터 하나
  - `embed_documents`: 청크 리스트를 묶어 한 번의 요청으로 처리(배치)
  - 교안: [2장 4강](../lecture/ch02/204.md) (퀴즈 Q2)

### 04 · 벡터 저장소 (PGVector)

- [ ] **`index()` 결과 해석**
  - 결과는 `num_added / num_updated / num_skipped / num_deleted` 개수로 나온다
  - 내용이 바뀐 문서는 update가 아니라 **삭제 1 + 추가 1**로 처리된다
  - 바뀌었는지는 SQLRecordManager가 기록한 **해시**로 판단한다
  - 주의: 교안 본문은 "update"라고 쓰지만 실제 출력은 삭제 + 추가다
  - 교안: [2장 7강](../lecture/ch02/207.md)

### 06 · BM25와 하이브리드 검색

- [ ] **가중합 (Weighted Sum)과 RRF 상수 60**
  - 결합 방식은 두 가지다: 가중합(`키워드×0.3 + 벡터×0.7`)과 RRF
  - RRF에서 60을 쓰는 이유: 1위와 2위 점수 차이가 지나치게 벌어지지 않게 하려고
  - 교안: [4장 2강](../lecture/ch04/402.md), [5장 3강](../lecture/ch05/503.md)

### 07 · 리랭킹과 압축

- [ ] **2단계 검색의 숫자 기준과 Cross-Encoder 직접 쓰기**
  - 1단계는 Top-N 10~30개를 빠르게, 2단계는 Top-K 2~5개로 줄인다
  - LangChain 래퍼 없이 `CrossEncoder(...).predict([[질문, 문서], ...])`로 점수를 낸 뒤 `sorted`로 정렬하는 방법
  - 예: "맛있는 사과 고르는 요령" 질문에서 사과 문서 0.1274, 아이폰(애플) 문서 0.0001. 동음이의어를 구분한다
  - 교안: [4장 3강](../lecture/ch04/403.md), [5장 4강](../lecture/ch05/504.md)
- [ ] **압축의 효과와 다른 압축기**
  - 효과 4가지: 토큰·비용·지연↓, Lost in the Middle 완화, 환각 억제, 노이즈 제거
  - 오답 함정: 압축은 DB 저장 용량을 줄이는 기술이 **아니다**
  - LLM 말고 임베딩 유사도로 거르는 압축기도 있다 (`EmbeddingsFilter`)
  - 교안: [5장 5강](../lecture/ch05/505.md) (퀴즈 Q1)

### 09 · RAG 평가 지표

- [ ] **정밀도·재현율·F1 숫자로 보기**
  - 정밀도 = 순도(가져온 것 중 맞은 비율), 재현율 = 포괄 범위(맞는 것 중 가져온 비율)
  - P 0.10, R 0.90이면 산술평균은 0.50이지만 F1은 0.18이다. 한쪽이 낮으면 F1이 확 떨어진다
  - 문서 ID 집합의 교집합으로 P·R을 계산하는 코드
  - 교안: [6장 1강](../lecture/ch06/601.md)
