## 2. RRF와 가중치(Weights) 튜닝 구조

<aside>
💡

<u>**RRF(Reciprocal Rank Fusion, 상호 순위 융합)**</u>
점수 측정 기준이 완전히 다른 여러 검색기를 '순위(등수)'를 기준으로 공정하고 균형 있게 합쳐주는 알고리즘입니다. 0부터 수십 점까지 올라가는 BM25의 키워드 빈도 점수와 0과 1 사이로 측정되는 벡터의 코사인 유사도 점수는 직접 비교할 수 없기 때문에, 절대 점수 대신 '몇 등을 했는가'의 순위 역수를 매겨 공정한 단일 순위표로 통합합니다.

</aside>

### 2.1 서로 다른 점수 체계의 문제점과 RRF의 필요성

<aside>

- **점수 체계의 불일치**: BM25 점수는 문장 길이나 단어 빈도에 따라 0점부터 수십 점까지 치솟지만, 벡터 유사도는 0과 1 사이로 측정됩니다.
- **RRF(Reciprocal Rank Fusion) 해결책**: 절대적인 점수를 배제하고 각 검색기에서의 '등수'를 역수로 변환($\frac{1}{순위 + k}$)하여 합산합니다.
- **상수** $k$**의 역할**: 일반적으로 $k=60$을 적용하여 1위와 2위의 점수 차이가 과도하게 벌어지는 현상을 방지합니다.
</aside>

### 2.2 질의 유형에 따른 가중치 분배 전략

<aside>

- **키워드 중심 질의**: 사규 명칭, 에러 코드, 고유 시스템명 검색 시 BM25의 가중치를 상향(`weights=[0.8, 0.2]`)합니다.
- **의미 중심 질의**: 구체적인 단어가 기억나지 않고 의도 중심일 경우 벡터 검색의 가중치를 상향(`weights=[0.2, 0.8]`)합니다.

| **질의 유형** | **추천 가중치 (BM25 : Vector)** | **주요 특징** |
| --- | --- | --- |
| **고유명사·약어 중심** | `0.8 : 0.2` 또는 `0.7 : 0.3` | 특정 단어가 본문에 반드시 존재해야 할 때 효과적입니다. |
| **일반적인 균형 검색** | `0.5 : 0.5` | 단어 일치와 의미 유사도를 균등하게 고려합니다. |
| **의도·서술형 뉘앙스** | `0.2 : 0.8` 또는 `0.3 : 0.7` | 단어가 일치하지 않아도 맥락적 동의어를 찾아야 할 때 효과적입니다. |
</aside>

## 3. 코드로 구현하는 RRF 가중치 튜닝과 LLM 연동

<aside>
💡

키워드 검색(BM25)과 벡터 검색 사이의 가중치(가령 가중치 계수 $\alpha$)를 다양하게 조절해 보며, 문서들의 순위표가 어떻게 역전되고 재배치되는지 직접 관찰합니다. 규정 번호나 고유명사를 찾는 '단어 일치형 질의'에는 키워드 비중을 높이고, 맥락과 의도를 파악해야 하는 '의미 중심 질의'에는 벡터 비중을 높이는 최적의 밸런스를 찾은 뒤, LLM 모델에 문맥을 전달하여 신뢰도 높은 최종 답변을 완성합니다.

</aside>

### 3.1 텍스트 데이터 준비 및 개별 검색기 생성

<aside>

사내 IT 규정 문서를 바탕으로 BM25 검색기와 PostgreSQL 벡터 저장소를 각각 초기화합니다. 

```python
import os
from dotenv import load_dotenv
from langchain_core.documents import Document
from langchain_community.retrievers import BM25Retriever
from langchain_openai import OpenAIEmbeddings
from langchain_postgres import PGVector

load_dotenv()

connection = os.getenv("DATABASE_URL")

# 실습에 사용할 규정 문서를 정의합니다.
raw_documents = [
    Document(page_content="보안 규정: 업무용 PC는 3개월마다 비밀번호를 변경해야 하며 특수문자를 포함해야 합니다."),
    Document(page_content="원격 근무 가이드: 재택 근무 시 반드시 사내 VPN을 연결하여 사내 인트라넷에 접속해야 합니다."),
    Document(page_content="장비 지급 규정: 신규 입사자에게는 노트북 1대와 외장 모니터 1대가 기본 지급됩니다."),
    Document(page_content="계정 관리: 사내 계정 5회 연속 로그인 실패 시 계정이 잠기며 IT 지원팀에 잠금 해제를 요청해야 합니다.")
]

# BM25 키워드 검색기 생성
def custom_tokenizer(text: str) -> list[str]:
    # 공백 기준으로 단어를 분리합니다.
    return text.split()

bm25_retriever = BM25Retriever.from_documents(
    documents=raw_documents,
    preprocess_func=custom_tokenizer
)
bm25_retriever.k = 3

# PostgreSQL Vector 검색기 생성
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = PGVector.from_documents(
    documents=raw_documents,
    embedding=embeddings,
    connection=connection,
    collection_name="it_regulations_tuning",
    use_jsonb=True
)
vector_retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
```

</aside>

### 3.2 질의 유형별 EnsembleRetriever 가중치 튜닝

<aside>

정확한 고유 키워드(`VPN`)가 들어간 질의와 우회적 표현(`집에서 컴퓨터로 회사 접속`) 질의에 대해 가중치를 다르게 적용합니다.

```python
from langchain_classic.retrievers import EnsembleRetriever

# 키워드 중심 튜닝: BM25에 0.8, 벡터에 0.2 가중치 부여
keyword_tuned_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.8, 0.2]
)

# 의미 중심 튜닝: BM25에 0.2, 벡터에 0.8 가중치 부여
semantic_tuned_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.2, 0.8]
)

# 질의문 1: 정확한 키워드가 명시된 질문
query_keyword = "사내 VPN 연결 가이드"
docs_keyword = keyword_tuned_retriever.invoke(query_keyword)

print(f"[키워드 중심 튜닝 결과 (0.8 : 0.2)] 검색어: {query_keyword}")
for idx, doc in enumerate(docs_keyword):
    print(f"{idx + 1}순위: {doc.page_content}")

print("\n" + "=" * 60 + "\n")

# 질의문 2: 단어는 일치하지 않지만 의미가 유사한 질문
query_semantic = "집에서 컴퓨터로 회사 내부망 들어갈 때 원격 규칙"
docs_semantic = semantic_tuned_retriever.invoke(query_semantic)

print(f"[의미 중심 튜닝 결과 (0.2 : 0.8)] 검색어: {query_semantic}")
for idx, doc in enumerate(docs_semantic):
    print(f"{idx + 1}순위: {doc.page_content}")
```

### 3.3 RRF 공식 기반 종합 점수 계산 원리 검증

<aside>

랭체인 내부에서 실행되는 RRF 가중 합산 원리를 코드로 명시하여 계산 과정을 확인합니다.

```python
# RRF 기본 상수 (일반적으로 60을 사용)
C_CONSTANT = 60

def calculate_rrf_score(rank: int, weight: float, c: int = C_CONSTANT) -> float:
    # 공식: 가중치 * (1 / (순위 + 상수))
    return weight * (1.0 / (rank + c))

# 문서 A가 BM25 1위, Vector 2위일 때 가중치 [0.8, 0.2] 적용 시 점수 계산
doc_a_bm25_rank = 1
doc_a_vector_rank = 2
score_a = calculate_rrf_score(doc_a_bm25_rank, 0.8) + calculate_rrf_score(doc_a_vector_rank, 0.2)

# 문서 B가 BM25 3위, Vector 1위일 때 가중치 [0.8, 0.2] 적용 시 점수 계산
doc_b_bm25_rank = 3
doc_b_vector_rank = 1
score_b = calculate_rrf_score(doc_b_bm25_rank, 0.8) + calculate_rrf_score(doc_b_vector_rank, 0.2)

print(f"문서 A의 RRF 융합 점수: {score_a:.6f}")
print(f"문서 B의 RRF 융합 점수: {score_b:.6f}")
print(f"최종 우선 문서: {'문서 A' if score_a > score_b else '문서 B'}")
```

```
문서 A의 RRF 융합 점수: 0.016341
문서 B의 RRF 융합 점수: 0.015977
최종 우선 문서: 문서 A
```

### 3.4 LLM 모델 연동 질의응답 파이프라인 완성

<aside>

최적화된 검색 결과 문맥을 LLM 모델에 전달하여 명확한 근거 답변을 생성합니다.

```python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import PromptTemplate

model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# QA 프롬프트 템플릿 정의
qa_prompt = PromptTemplate.from_template(
    "다음 제공된 [참고 문서]를 바탕으로 [질문]에 대해 간결하고 정확하게 답변하세요.\n\n"
    "[참고 문서]: \n{context}\n\n"
    "[질문]: \n{question}\n\n"
    "[답변]:"
)

# 의미 중심 튜닝으로 추출한 문서를 문맥 텍스트로 결합
selected_query = "집에서 컴퓨터로 회사 내부망 들어갈 때 원격 규칙"
selected_docs = semantic_tuned_retriever.invoke(selected_query)
context_text = "\n".join([doc.page_content for doc in selected_docs])

# 체인 연결 및 호출
qa_chain = qa_prompt | model
response = qa_chain.invoke({
    "context": context_text,
    "question": selected_query
})

print(f"[질문]: {selected_query}\n")
print("[모델 답변]")
print(response.content)
```

```
[질문]: 집에서 컴퓨터로 회사 내부망 들어갈 때 원격 규칙

[모델 답변]
요약해서 다음을 준수하세요.
```

### 4.2 개념 요약 키워드

- **RRF (Reciprocal Rank Fusion)**: 점수 체계가 다른 여러 검색기의 결과 순위를 역수로 변환하여 공평하게 합산하는 순위 융합 기법
- **가중치 튜닝 (Weight Tuning)**: 질문 의도(단어 일치 vs 문맥 일치)에 맞춰 각 검색기의 기여도를 배분하는 최적화 작업
