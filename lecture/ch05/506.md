## 이번에 배울 것은?

<aside>
❗ **배달 앱에서 '마라탕'을 검색할 때와 '얼큰하고 얼얼한 국물 요리'를 검색할 때, 결과가 완전히 다르게 나왔던 경험이 있나요?**

특정 상호명이나 메뉴 이름을 정확히 알 때는 단어 그대로 검색하는 것이 정확하지만, 구체적인 이름이 생각나지 않을 때는 느낌이나 의미를 풀어서 검색해야 원하는 가게를 찾을 수 있습니다.

지난 강에서는 1차로 검색된 긴 문서에서 잡음을 제거하고 질문에 꼭 필요한 핵심 문장만 잘라내는 맥락 압축(Contextual Compression)을 배웠습니다.

하지만 압축을 진행하기에 앞서 질문의 형태와 맞지 않는 검색 방식을 선택하면, 시작 단계부터 엉뚱한 문서가 걸려 나오는 검색 실패가 발생합니다.

이번 강에서는 질문의 성격(키워드 중심, 의미 중심 등)에 따라 키워드 검색과 벡터 검색이 어떤 결과를 내는지 비교하고, LLM 모델을 활용해 검색 실패 원인을 분석하는 리포트를 만들어 봅니다.

</aside>

## 2. 질의(Query) 유형의 이해와 실패 메커니즘

<aside>
💡

<u>**질문의 구조와 성격에 따라 검색 엔진이 인식하는 방식이 다릅니다.**</u>
단어 일치 여부와 문맥적 뉘앙스에 따라 키워드 검색과 벡터 검색의 성능 차이가 발생합니다.

</aside>

### 2.1 대표적인 3가지 질의 유형

<aside>

- **고유명사·단순 키워드형 (Exact Keyword)**: 문서 내에 명시된 특정 코드, 약어, 고유 명칭을 포함하는 질문입니다.
- **의미 탐색형 (Semantic/Intent)**: 원본 문서의 단어와 일치하지 않으나 일상적인 구어체나 동의어로 의미를 묻는 질문입니다.
- **복합 조건형 (Complex Multi-condition)**: 다중 제약 조건이나 상황 설명이 혼합되어 문맥 해석이 필요한 질문입니다.
</aside>

### 2.2 검색 전략별 비교 및 적합도

<aside>

| **비교 항목** | **키워드 검색 (BM25)** | **벡터 검색 (Vector/Semantic)** |
| --- | --- | --- |
| **작동 원리** | 텍스트 내 특정 단어의 빈도와 희소성 계산 | 문장을 다차원 숫자 배열로 변환 후 의미 거리 계산 |
| **강점 영역** | 고유명사, 약어, 규정 조항 번호 검색 | 동의어, 유의어, 구어체 기반 문맥 검색 |
| **주요 실패 원인** | 단어 불일치 시 검색 누락 (Vocabulary Mismatch) | 전문 용어 왜곡, 지나치게 포괄적인 유사도 매칭 |
</aside>

## 3. 코드로 구현하는 질의 비교 및 진단 파이프라인

<aside>
💡

<u>**동일한 문서 집합에 대해 검색기별 결과를 수집하고 LLM 모델로 실패 원인을 분석합니다.**</u>
키워드 검색기(BM25)와 벡터 검색기를 구축하여 유형별 질의를 테스트하고 자동 진단 리포트를 생성합니다.

</aside>

### 3.1 텍스트 데이터 준비 및 다중 검색기 생성

<aside>

- **실습 데이터 정의**: 규정 및 복지 정보가 포함된 3개의 문서를 생성합니다.
- **검색기 구성**: 텍스트 일치 기반의 BM25Retriever와 문맥 의미 기반의 InMemoryVectorStore를 준비합니다.

```python
import os
from dotenv import load_dotenv
from langchain_core.documents import Document
from langchain_community.retrievers import BM25Retriever
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings

# .env 환경 변수를 불러옵니다.
load_dotenv()

# 비교 분석에 사용할 사내 안내 문서를 정의합니다.
raw_documents = [
    Document(
        page_content="신규 입사자 OJT 교육 안내: 하반기 공채 신입사원 대상 OJT는 개더타운 메타버스 연수원에서 온라인 비대면으로 진행됩니다.",
        metadata={"category": "교육", "doc_id": 1}
    ),
    Document(
        page_content="사내 식당 운영 지침: 중식 운영 시간은 11시 30분부터 13시 30분까지이며 외부 방문객의 1회 식권 가격은 8,000원입니다.",
        metadata={"category": "복지", "doc_id": 2}
    ),
    Document(
        page_content="정보보안 규정: 직원이 퇴사하는 경우 모든 사내 전산망 및 인트라넷 계정 권한은 퇴사 당일 18시를 기점으로 영구 회수됩니다.",
        metadata={"category": "보안", "doc_id": 3}
    )
]

# 띄어쓰기 기준 공백 분리 토크나이저 함수를 정의합니다.
def simple_tokenizer(text: str) -> list[str]:
    # 텍스트를 공백 단위로 분할하여 리스트로 반환합니다.
    return text.split()

# 키워드 검색기 (BM25)를 생성하고 반환 개수를 1개로 설정합니다.
bm25_retriever = BM25Retriever.from_documents(
    documents=raw_documents,
    preprocess_func=simple_tokenizer
)
bm25_retriever.k = 1

# 벡터 검색기를 생성합니다. OpenAI 임베딩 모델을 사용합니다.
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = InMemoryVectorStore.from_documents(
    documents=raw_documents,
    embedding=embeddings
)
vector_retriever = vector_store.as_retriever(search_kwargs={"k": 1})
```

</aside>

### 3.2 질의 유형별 대조 실행

<aside>

**유형별 테스트 질의 세트 구성**: 고유명사형, 의미 탐색형, 복합 조건형 질의를 실행하여 결과를 대조합니다.

```python
# 질의 유형별 테스트 케이스를 정의합니다.
test_cases = [
    {"type": "고유명사형", "query": "개더타운 접속 일정"},
    {"type": "의미 탐색형", "query": "새로 들어온 신입 직원 교육은 어디서 하나요?"},
    {"type": "복합 조건형", "query": "퇴사할 때 사내 계정 정리는 몇 시에 진행돼?"}
]

# 각 질의에 대해 두 검색기의 결과를 비교 출력합니다.
print("=== [질의 유형별 검색 결과 대조] ===")
comparison_records = []
for case in test_cases:
    q_type = case["type"]
    query = case["query"]

    # BM25 키워드 검색 실행
    bm25_docs = bm25_retriever.invoke(query)
    bm25_content = bm25_docs[0].page_content if bm25_docs else "결과 없음"

    # 벡터 유사도 검색 실행
    vector_docs = vector_retriever.invoke(query)
    vector_content = vector_docs[0].page_content if vector_docs else "결과 없음"

    # 결과를 딕셔너리로 저장합니다.
    comparison_records.append({
        "type": q_type,
        "query": query,
        "bm25": bm25_content,
        "vector": vector_content
    })
    
    print(f"질문 유형: {q_type}")
    print(f"질문 내용: {query}")
    print(f" - [BM25 결과]: {bm25_content}")
    print(f" - [Vector 결과]: {vector_content}")
    print("-" * 60)
```

### 3.3 LLM 모델 기반 검색 실패 원인 분석 리포트 생성

<aside>

LLM 모델에 비교 결과를 전달하여 각 검색기가 성공하거나 실패한 이유를 전문 리포트 형식으로 추출합니다.

```python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import PromptTemplate

model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# 검색 실패 분석을 수행할 프롬프트 템플릿을 정의합니다.
report_prompt = PromptTemplate.from_template(
    "다음은 동일한 [질문]에 대해 키워드 검색(BM25)과 벡터 검색이 도출한 결과입니다.\n\n"
    "[질문 유형]: {query_type}\n"
    "[질문]: {query}\n"
    "[BM25 검색 결과]: {bm25_result}\n"
    "[벡터 검색 결과]: {vector_result}\n\n"
    "두 검색 결과의 적합성을 평가하고, 특정 검색기가 실패했다면 그 원인(단어 불일치, 어휘 유사도 왜곡 등)을 "
    "2줄 이내의 객관적인 문장으로 분석하여 리포트를 작성하세요.\n\n"
    "[진단 리포트]:"
)

# LLM 체인을 구성합니다.
diagnostic_chain = report_prompt | model

# 두 번째 케이스(의미 탐색형)의 실패 원인을 진단합니다.
target_case = comparison_records[1]

response = diagnostic_chain.invoke({
    "query_type": target_case["type"],
    "query": target_case["query"],
    "bm25_result": target_case["bm25"],
    "vector_result": target_case["vector"]
})

print(f"=== [검색 진단 리포트] ===")
print(f"질문: {target_case['query']}")
print(response.content)
```

```
=== [검색 진단 리포트] ===
질문: 새로 들어온 신입 직원 교육은 어디서 하나요?
[진단 리포트]

요약 질의: "새로 들어온 신입 직원 교육은 어디서 하나요?"

1) BM25 검색 결과 적합성: 부적절  
- 이유(원인): 문서 내용은 '퇴사 시 계정 회수'에 관한 것으로 쿼리의 핵심(신입, 교육, 장소)과 표면적 어휘가 일치하지 않아 BM25의 문자열/빈도 기반 매칭이 관련 문서를 찾지 못함.

2) 벡터 검색 결과 적합성: 적절  
- 이유(원인): 의미 기반 임베딩으로 '신입 직원'↔'신규 입사자', '교육 장소' 개념을 포착해 OJT 진행 장소(개더타운 메타버스 연수원)를 정확히 반환함.

결론: 이번 사례에서는 BM25가 어휘 불일치로 실패했고, 벡터 검색이 의미적 유사도를 통해 올바른 답변을 제공함.
```

**Q1. 사용자가 "점심 식권 가격 알려줘" 대신 "낮에 먹는 밥값 얼마예요?"라고 질문했을 때, 키워드 검색(BM25)이 문서를 찾지 못하는 주된 원인은 무엇인가요?**

---

- [ ]  (1) 데이터베이스의 포트 번호가 올바르게 연결되지 않아서
- [ ]  (2) 질문에 사용된 단어가 원본 문서에 존재하는 단어와 형태학적으로 일치하지 않아서
- [ ]  (3) 임베딩 벡터의 차원 수가 지나치게 높아서
- [ ]  (4) gpt-5-mini 모델의 호출 비용 한도를 초과해서

- **답안 설명**
    
    **정답:** 2번
    
    키워드 검색은 동일한 단어의 출현 빈도를 기반으로 작동하므로, '점심 식권'과 '낮에 먹는 밥값'처럼 뜻은 같으나 표기가 다른 어휘 불일치(Vocabulary Mismatch) 상황에서 검색에 실패합니다.
    
</aside>

<aside>

**Q2. 고유명사나 특정 코드 번호(예: 오류 코드 'ERR_902', 규정 조항 '제14조 제2항')를 검색할 때 벡터 검색보다 키워드 검색(BM25)이 더 안정적인 이유는 무엇인가요?**

---

- [ ]  (1) 벡터 임베딩 모델이 고유 문자열의 미세한 차이를 단순 노이즈로 처리하거나 뭉갤 수 있기 때문에
- [ ]  (2) 키워드 검색이 임베딩 모델보다 더 많은 GPU 메모리를 사용하기 때문에
- [ ]  (3) 벡터 검색은 한글 텍스트를 숫자로 변환할 수 없기 때문에
- [ ]  (4) 키워드 검색은 검색 결과를 최대 1개만 반환하도록 제한되어 있기 때문에

- **답안 설명**
    
    **정답:** 1번
    
    임베딩 모델은 문장의 전체적인 맥락을 압축하는 과정에서 희귀한 고유 코드나 일련번호의 세부 문자를 보존하지 못하고 주변 단어의 평균적 의미로 흡수해 버리는 경향이 있습니다.
    
</aside>

**Q3. 다중 검색 전략을 평가할 때 gpt-5-mini와 같은 언어 모델을 분석 도구로 활용하는 목적으로 가장 적절한 것은 무엇인가요?**

---

- [ ]  (2) 사용자 질문의 글자 수를 임의로 늘려 저장하기 위해
- [ ]  (3) 검색 결과와 질문 사이의 논리적 일치성을 판별하고 검색 실패 원인을 객관적으로 도출하기 위해
- [ ]  (4) 데이터베이스 테이블의 스키마를 자동으로 변경하기 위해

- **답안 설명**
    
    **정답:** 3번
    
    언어 모델은 질문의 의도와 검색된 문서 내용 간의 의미적 적합성을 판별하고, 검색기가 왜 엉뚱한 문서를 반환했는지 원인을 분석하는 평가자로 기능할 수 있습니다.
    
</aside>

### 4.2 개념 요약 키워드

- **질의 유형 (Query Type)**: 질문이 요구하는 정보의 형태에 따라 고유명사형, 의미 탐색형, 복합 조건형 등으로 나뉘는 분류 기준
- **어휘 불일치 (Vocabulary Mismatch)**: 사용자의 질문 어휘와 문서 내 어휘의 의미는 같으나 글자 형태가 달라 키워드 검색이 실패하는 현상
- **검색 실패 분석 (Retrieval Failure Analysis)**: 검색기가 잘못된 문서를 도출한 기술적 원인을 규명하여 향후 하이브리드 검색이나 가중치 튜닝의 근거로 삼는 작업
