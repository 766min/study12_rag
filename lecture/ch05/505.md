## 2. 맥락 압축(Contextual Compression)의 구조

<aside>
💡

<u>**맥락 압축(Contextual Compression)**</u>
검색된 문서 전체를 그대로 전달하지 않고, 질문과 연관된 핵심 내용만 발췌하거나 불필요한 문장을 제거하여 전달하는 검색 최적화 기술입니다.

</aside>

### 2.1 문서 전체 전달 방식의 한계

<aside>

- **토큰 낭비 및 비용 증가**: 질문과 상관없는 수천 자의 본문이 프롬프트에 들어가면 API 호출 비용이 불필요하게 늘어납니다.
- **Lost in the Middle (중간 정보 누락)**: 인공지능 모델은 제공된 긴 문맥의 중간에 위치한 세부 사실을 망각하는 경향이 있습니다.
- **환각(Hallucination) 유발**: 문서 내에 포함된 다른 주제의 수치나 규정이 모델의 판단을 흐려 오답을 생성할 확률이 높아집니다.
</aside>

### 2.2 맥락 압축의 2단계 동작 원리

<aside>

- **1단계 (기본 검색)**: 키워드 검색기(BM25) 또는 벡터 검색기가 질문과 관련된 후보 문서를 빠르게 가져옵니다.
- **2단계 (문맥 압축)**: 문서 압축기(Compressor)가 질문을 기준으로 문서를 읽고, 무관한 문장을 삭제하거나 핵심 문장만 추출합니다.

| **비교 항목** | **기존 문서 전체 전달 (Full Document)** | **맥락 압축 (Contextual Compression)** |
| --- | --- | --- |
| **전달 데이터** | 검색된 원본 문서 청크 전체 (수천 자) | 질문에 맞게 정제된 핵심 문장 (수십~수백 자) |
| **토큰 소모량** | 큼 (비용 및 응답 지연 시간 증가) | 적음 (비용 절감 및 빠른 응답 속도) |
| **노이즈 비율** | 높음 (질문과 무관한 내용 다수 포함) | 최소화 (정답 근거 문장만 선별 유지) |
| **답변 신뢰도** | 주변 잡음 정보로 인해 왜곡 위험 존재 | 명확한 근거에 집중하여 정확도 향상 |
</aside>

## 3. 코드로 구현하는 맥락 압축과 질의응답 파이프라인

<aside>
💡

랭체인의 **ContextualCompressionRetriever**에 LLM 기반 압축기를 결합하고, LLM 모델과 연결하여 최적화된 질의응답 체인을 구현합니다.

</aside>

### 3.1 텍스트 데이터 준비 및 기본 검색기 생성

<aside>

복합적인 규정이 하나의 문서 안에 혼재되어 있는 사내 가이드 문서를 준비하고 1차 기본 검색기를 구성합니다.

```python
# 문서 객체와 기본 키워드 검색기 모듈을 가져옵니다.
from langchain_core.documents import Document
from langchain_community.retrievers import BM25Retriever

# 여러 주제가 혼합된 실습용 사내 규정 문서를 정의합니다.
raw_documents = [
    Document(
        page_content="복지 제도 안내: 사내 복지 포인트는 매년 1월 1일에 100만 포인트가 지급됩니다. "
                     "포인트는 자기계발 및 문화생활에 사용 가능하며, 미사용 잔여 포인트는 당해 연도 12월 31일에 전액 소멸되어 다음 해로 이월되지 않습니다."
    ),
    Document(
        page_content="휴가 규정 안내: 연차 유급휴가는 1년간 80% 이상 출근 시 15일이 부여됩니다. "
                     "경조사 휴가는 사유 발생일로부터 사용해야 하며, 미사용 연차는 연말에 수당으로 정산 지급됩니다."
    ),
    Document(
        page_content="근무 환경 가이드: 사무실 내 회의실 예약은 사내 인트라넷 시스템을 통해 최소 1시간 전에 신청해야 합니다. "
                     "점심시간은 12시 30분부터 13시 30분까지이며 부서별 자율 운영이 가능합니다."
    )
]

# 공백 기준 단순 토크나이저 함수를 정의합니다.
def custom_tokenizer(text: str) -> list[str]:
    # 문장을 띄어쓰기 단위로 분리하여 단어 리스트를 반환합니다.
    return text.split()

# 1단계 기본 검색기(BM25)를 생성하고 검색 개수를 1개로 설정합니다.
base_retriever = BM25Retriever.from_documents(
    documents=raw_documents,
    preprocess_func=custom_tokenizer
)
base_retriever.k = 2
```

</aside>

### 3.2 LLM 모델 기반 문서 압축기 생성

<aside>

문서를 읽고 질문에 필요한 부분만 잘라내는 압축기(LLMChainExtractor)를 설정합니다.

```python
import os
from dotenv import load_dotenv

from langchain.chat_models import init_chat_model
# LLM을 활용해 문맥을 오려내는 압축기 모듈을 가져옵니다.
from langchain_classic.retrievers.document_compressors import LLMChainExtractor
# 기본 검색기와 압축기를 결합하는 래퍼 클래스를 가져옵니다.
from langchain_classic.retrievers import ContextualCompressionRetriever

load_dotenv()

model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# 문서 압축기를 생성합니다.
compressor = LLMChainExtractor.from_llm(model)

# 1단계 검색기(base_retriever)와 2단계 압축기(compressor)를 연결합니다.
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=base_retriever
)
```

</aside>

### 3.3 압축 전후 검색 결과 비교 분석

<aside>

질문과 직접적인 관련이 없는 문장이 압축기를 통과하면서 어떻게 정제되는지 확인합니다.

```python
# 질문 정의: 복지 포인트의 다음 해 이월 가능 여부 질문
query = "사내 복지 포인트 남으면 다음 해로 넘겨서 쓸 수 있나요?"

# 압축 전 기본 검색기(BM25) 결과 확인
docs_before = base_retriever.invoke(query)
print(f"=== [1단계 기본 검색 (압축 전 원본)] ===")
for doc in docs_before:
    print(doc.page_content)

print("\n" + "=" * 60 + "\n")

# 2단계 맥락 압축기(Contextual Compression) 결과 확인
docs_after = compression_retriever.invoke(query)
print(f"=== [2단계 맥락 압축 (압축 후 핵심 문맥)] ===")
for doc in docs_after:
    print(doc.page_content)
```

```

복지 제도 안내: 사내 복지 포인트는 매년 1월 1일에 100만 포인트가 지급됩니다. 포인트는 자기계발 및 문화생활에 사용 가능하며, 미사용 잔여 포인트는 당해 연도 12월 31일에 전액 소멸되어 다음 해로 이월되지 않습니다.

============================================================

=== [2단계 맥락 압축 (압축 후 핵심 문맥)] ===
```

### 3.4 LLM 모델 연동 질의응답 파이프라인 완성

<aside>

압축된 고순도 문맥만을 프롬프트에 주입하여 최종 답변을 생성합니다.

```python
# 프롬프트 템플릿 모듈을 가져옵니다.
from langchain_core.prompts import PromptTemplate

# 문맥과 질문을 주입할 프롬프트 템플릿을 생성합니다.
qa_prompt = PromptTemplate.from_template(
    "다음 제공된 [참고 문서]를 바탕으로 [질문]에 대해 명확하고 간결하게 답변하세요.\n\n"
    "[참고 문서]:\n{context}\n\n"
    "[질문]:\n{question}\n\n"
    "[답변]:"
)

# 압축 검색기를 통해 핵심 문맥을 추출합니다.
compressed_docs = compression_retriever.invoke(query)
context_text = "\n".join([doc.page_content for doc in compressed_docs])

# 프롬프트와 gpt-5-mini 모델을 연결해 질의응답 체인을 구성합니다.
qa_chain = qa_prompt | model

# 체인을 실행하고 결과를 출력합니다.
response = qa_chain.invoke({
    "context": context_text,
    "question": query
})

print(f"[질문]: {query}\n")
print("[생성 답변]")
print(response.content)
```

```
[질문]: 사내 복지 포인트 남으면 다음 해로 넘겨서 쓸 수 있나요?

[생성 답변]
아니요. 매년 1월 1일에 100만 포인트가 지급되며, 미사용 잔여 포인트는 당해 연도 12월 31일에 전액 소멸되어 다음 해로 이월되지 않습니다.
```

<aside>
💡

**Q2. 리랭킹(Re-ranking)과 맥락 압축(Contextual Compression)의 기능적 차이로 가장 적절한 것은 무엇인가요?**

---

- [ ]  (1) 리랭킹은 문서 단위의 순서를 재배열하고, 맥락 압축은 문서 내부의 불필요한 문장을 잘라낸다.
- [ ]  (2) 리랭킹은 파이썬 코드로 동작하고, 맥락 압축은 C 언어로만 동작한다.
- [ ]  (3) 리랭킹은 키워드만 검색하고, 맥락 압축은 이미지만 검색한다.
- [ ]  (4) 리랭킹은 속도를 느리게 만들고, 맥락 압축은 검색 기능을 완전히 중단시킨다.

- **답안 설명**
    
    **정답:** 1번

### 4.2 개념 요약 키워드

- **맥락 압축 (Contextual Compression)**: 검색된 문서 청크 전체를 전달하지 않고 질문에 꼭 필요한 핵심 구절만 발췌해 LLM에 넘겨주는 최적화 기법
- **문서 압축기 (Document Compressor)**: LLM 또는 유사도 필터를 사용하여 문서 본문 내 불필요한 잡음 텍스트를 실시간으로 삭제하는 모듈
- **노이즈 제거 (Denoising)**: 질문과 무관한 주변 문장을 프롬프트에서 배제하여 환각을 억제하고 답변의 정확도를 극대화하는 작업

### 4.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **맥락 압축** | Contextual Compression | 검색된 원본 문서에서 질문과 관련 없는 문장을 걸러내고 핵심 근거만 남겨 프롬프트에 주입하는 최적화 기법입니다. |
| **문서 압축기** | Document Compressor | 언어 모델이나 임베딩 유사도를 활용하여 문서 본문에서 유의미한 정보만 발췌하거나 필터링하는 도구입니다. |
| **압축 리트리버** | Contextual Compression Retriever | 1차 기본 검색기와 2차 문서 압축기를 단일 인터페이스로 묶어 검색과 문맥 정제를 동시에 수행하는 랭체인 검색기입니다. |
| **중간 망각 현상** | Lost in the Middle | 입력된 프롬프트가 지나치게 길 경우 인공지능이 중간에 위치한 핵심 단서를 놓치고 답변 품질이 저하되는 현상입니다. |
