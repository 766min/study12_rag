## 2. 임베딩(Embedding)과 벡터 표현

<aside>
💡

<u>**임베딩은 자연어 텍스트의 의미론적(Semantic) 맥락을 고차원 벡터 공간의 수치 좌표로 매핑하는 기술입니다.**</u> 의미적 유사도가 높은 데이터일수록 공간상에서 인접하게 배치되므로, 벡터 간 거리 연산을 통해 텍스트의 유사성을 정량적으로 측정할 수 있습니다.

</aside>

### 2.1 텍스트에서 벡터로의 의미 변환

<aside>

<u>**임베딩 모델**</u>

<aside>
텍스트를 입력받아 의미 정보를 보존한 고정 길이 숫자 배열로 출력하는 특수 인공지능 모델입니다.

</aside>

<u>**벡터(Vector)**</u>

<aside>
`[-0.012, 0.034, 0.981, ...]` 형태로 표현되는 고유한 숫자 좌표 목록입니다.

</aside>

**<u>차원(Dimension)</u>**

<aside>
좌표 축의 개수를 의미하며, text-embedding-3-small 모델은 기본 1,536개의 좌표 축을 가집니다.

</aside>

</aside>

## 3. 임베딩 생성 실습

<aside>
💡

LangChain의 OpenAIEmbeddings 인터페이스를 호출하여 단일 텍스트 및 배치 청크 데이터의 벡터 임베딩을 수행합니다. 런타임 질의 처리를 위한 embed_query()와 대용량 문서 색인을 위한 embed_documents() 간의 메서드 시그니처, 처리 규격, 내부 최적화 방식의 차이를 분석하고 검증합니다.

</aside>

### 3.1 임베딩 모델 연결 및 단일 질의 임베딩 (embed_query)

<aside>

**embed_query**: 질문 또는 단일 문장을 하나의 벡터로 변환할 때 호출하는 함수입니다

```python
import os
from dotenv import load_dotenv

from langchain_openai import OpenAIEmbeddings

load_dotenv()

# OpenAI의 경량 임베딩 모델을 초기화합니다.
embeddings_model = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

# 단일 테스트 질문을 정의합니다.
question = "특수 도서는 며칠 동안 대출할 수 있나요?"

# embed_query 함수로 질문 문장을 숫자 좌표로 변환합니다.
query_vector = embeddings_model.embed_query(question)

# 생성된 벡터의 차원 수와 데이터 일부를 확인합니다.
print(f"생성된 벡터 차원 수: {len(query_vector)}차원")
print(f"벡터 데이터 앞부분 5개 샘플: {query_vector[:5]}")
```

```
생성된 벡터 차원 수: 1536차원
벡터 데이터 앞부분 5개 샘플: [0.0213470458984375, 0.03790283203125, 0.04486083984375, -0.0160675048828125, 0.006534576416015625]
```

</aside>

### 3.2 다중 청크 배치 임베딩 (embed_documents)

<aside>

<u>**배치 처리(Batch Processing)**</u>

<aside>
여러 문장을 한 묶음으로 묶어 단 한 번의 네트워크 요청으로 처리하는 방식입니다.

</aside>

**<u>embed_documents</u>**

<aside>
지난 강에서 분할했던 여러 텍스트 조각들을 리스트 형태로 전달하여 다수의 벡터를 동시에 생성합니다.

</aside>

```python
# 지난 실습에서 분할했던 도서관 규정 청크 리스트를 정의합니다.
library_rule_chunks = [
    "[2026학년도 중앙도서관 대출 및 열람 규정]\n제1조(대출 자격) 본교 재학생 및 휴학생은 학생증을 제시한 후 도서를 대출할 수 있습니다.",
    "제2조(대출 권수 및 기간) 학부생은 1인당 최대 5권까지 대출할 수 있으며 대출 기간은 14일입니다.\n단, 학술 연구용 특수 도서는 7일간 대출 가능하며 연장은 불가능합니다.",
    "제3조(연체 및 제재) 반납 기한을 초과할 경우 연체 일수만큼 대출이 정지됩니다."
]

# embed_documents 함수를 사용해 모든 청크를 배치로 일괄 변환합니다.
doc_vectors = embeddings_model.embed_documents(library_rule_chunks)

# 생성된 결과의 개수와 각 벡터의 길이를 검증합니다.
print(f"변환 완료된 청크 수: {len(doc_vectors)}개")
print(f"각 청크 벡터의 차원 수: {len(doc_vectors[0])}차원")
```

```
변환 완료된 청크 수: 3개
각 청크 벡터의 차원 수: 1536차원
```

</aside>

## 4. 임베딩 비용 관리 및 캐싱(Caching) 실습

<aside>
💡

**한 번 계산된 임베딩 결과를 로컬 파일로 저장하여 중복 비용 발생을 원천 차단합니다.**
캐시 저장소(Cache Store)를 연결하여 동일한 문서의 재임베딩 작업을 방지합니다.

</aside>

### 4.1 로컬 파일 기반 캐시 저장소 연결

<aside>

- **CacheBackedEmbeddings**: 임베딩 요청 시 저장소를 먼저 확인하여 캐시된 데이터가 있으면 API 호출을 생략하는 래퍼 클래스입니다.
- **LocalFileStore**: 로컬 디스크의 특정 디렉터리를 영구 캐시 저장소로 활용하는 저장 도구입니다

```python
import time
from langchain_classic.embeddings import CacheBackedEmbeddings
from langchain_classic.storage import LocalFileStore

# 캐시 파일을 저장할 로컬 폴더 경로를 생성합니다.
store = LocalFileStore("./cache/")

# 임베딩 모델과 로컬 저장소를 결합한 캐시 지원 임베딩 객체를 생성합니다.
cached_embedder = CacheBackedEmbeddings.from_bytes_store(
    underlying_embeddings=embeddings_model, # 실제 임베딩 계산을 수행할 기본 모델
    document_embedding_cache=store, # 계산 결과를 바이트 형태로 보관할 저장소
    namespace="library_rules_v1"    # 캐시 영역을 분리하는 고유 식별자
)
```

</aside>

### 4.2 캐싱 적용 전후 실행 속도 및 비용 절감 검증

<aside>

- **1차 호출**: API를 호출하여 벡터를 생성한 후 로컬 디스크에 저장합니다.
- **2차 호출**: API 호출 없이 디스크에서 즉시 로드하므로 실행 속도가 대폭 단축되고 요금이 부과되지 않습니다.

```python
# 첫 번째 실행: 원본 모델 API 호출 및 로컬 캐시 기록
start_time = time.time()
vectors_first = cached_embedder.embed_documents(library_rule_chunks)
first_duration = time.time() - start_time
print(f"1차 실행 소요 시간 (API 호출 발생): {first_duration:.4f}초")

# 두 번째 실행: 로컬 캐시에서 즉시 불러오기
start_time = time.time()
vectors_cached = cached_embedder.embed_documents(library_rule_chunks)
cached_duration = time.time() - start_time
print(f"2차 실행 소요 시간 (캐시 재사용): {cached_duration:.4f}초")

# 두 실행 결과가 완전히 일치하는지 검증합니다.
is_identical = vectors_first == vectors_cached
print(f"데이터 정합성 일치 여부: {is_identical}")
```

```
1차 실행 소요 시간 (API 호출 발생): 0.7603초
2차 실행 소요 시간 (캐시 재사용): 0.0018초
데이터 정합성 일치 여부: True
```

</aside>

## 5. 임베딩 유사도 검색 및 LLM 모델 연동 실습

<aside>
💡

임베딩 벡터 간의 거리를 계산해 질문과 가장 관련성이 높은 문서 청크를 찾아낸 뒤, LLM을 통해 답변을 도출하고 검증합니다. 프롬프트에는 검색된 문맥(Context)만을 엄격히 주입하여, 모델의 환각(Hallucination)을 차단하고 신뢰할 수 있는 사실 기반의 답변을 완성합니다.

</aside>

### 5.1 코사인 유사도(Cosine Similarity) 기반 청크 검색

<aside>

벡터 간 사잇각의 코사인 값을 계산하여 의미적 유사도를 0과 1 사이의 값으로 산출합니다.

```python
import numpy as np

# 코사인 유사도 산출 함수를 정의합니다.
def calculate_cosine_similarity(vec_a, vec_b):
    norm_a = np.linalg.norm(vec_a)
    norm_b = np.linalg.norm(vec_b)
    return np.dot(vec_a, vec_b) / (norm_a * norm_b)

# 질문 벡터와 각 청크 벡터 간의 유사도를 계산합니다.
similarity_scores = [
    calculate_cosine_similarity(query_vector, doc_vec)
    for doc_vec in doc_vectors
]

# 가장 유사도가 높은 청크의 인덱스를 추출합니다.
best_chunk_idx = int(np.argmax(similarity_scores))

print("=== 청크별 유사도 계산 결과 ===")
for i, score in enumerate(similarity_scores):
    print(f"청크 {i+1} 유사도 점수: {score:.4f}")

# 가장 관련도가 높은 청크 본문을 확보합니다.
retrieved_context = library_rule_chunks[best_chunk_idx]
print(f"\n최종 검색된 최적 청크:\n{retrieved_context}")
```

```
=== 청크별 유사도 계산 결과 ===
청크 1 유사도 점수: 0.4162
청크 2 유사도 점수: 0.5561
청크 3 유사도 점수: 0.2501

최종 검색된 최적 청크:
제2조(대출 권수 및 기간) 학부생은 1인당 최대 5권까지 대출할 수 있으며 대출 기간은 14일입니다.
단, 학술 연구용 특수 도서는 7일간 대출 가능하며 연장은 불가능합니다.
```

</aside>

### 5.2 LLM 모델 연결 및 답변 체인 실행

<aside>

```python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

model = init_chat_model(
    model_provider="openai",
    model="gpt-5-mini",
    temperature=0
)

# 문맥 주입용 프롬프트 서식을 정의합니다.
qa_prompt = ChatPromptTemplate.from_messages([
    ("system", (
        "당신은 대학 도서관 규정 안내원입니다.\n"
        "제공된 [참고 청크]의 내용에만 엄격히 근거하여 질문에 답변하세요.\n"
        "내용에 언급되지 않은 사실은 절대 지어내지 마세요.\n\n"
        "[참고 청크]:\n{context}"
    )),
    ("user", "{question}")
])

# 프롬프트, 언어 모델, 파서를 파이프라인(|)으로 연결합니다.
rag_chain = qa_prompt | model | StrOutputParser()

# 검색된 청크와 질문을 주입하여 답변을 생성합니다.
response = rag_chain.invoke({
    "context": retrieved_context,
    "question": question
})

print("=== [최종 답변] ===")
print(response)
```

```
=== [최종 답변] ===
학술 연구용 특수 도서는 7일간 대출할 수 있으며 연장은 불가능합니다.
```

### 6.2 개념 요약 키워드

- **임베딩(Embedding)**: 단어나 문장이 지닌 의미적 특징을 다차원 공간의 숫자 벡터로 수치화하는 기술.
- **배치 임베딩(Batch Embedding)**: 여러 개의 청크를 단일 네트워크 요청으로 묶어 처리 속도를 향상하는 방식.
- **임베딩 캐싱(Embedding Caching)**: 기생성된 벡터를 로컬 저장소에 보관하여 중복 호출 비용을 방지하는 최적화 전략.
- **코사인 유사도(Cosine Similarity)**: 두 벡터 사이의 각도를 측정하여 문맥적 유사성을 0과 1 사이의 수치로 비교하는 계산법.

### 6.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **임베딩** | Embedding | 컴퓨터가 언어의 의미를 계산할 수 있도록 글자를 고차원 숫자 배열로 변환하는 기술입니다. |
| **벡터** | Vector | 크기와 방향을 가진 숫자 배열로, 임베딩을 통해 출력된 좌표값 자체를 의미합니다. |
| **차원** | Dimension | 벡터를 구성하는 숫자 좌표 요소의 총 개수로, 표현할 수 있는 의미의 정보량을 결정합니다. |
| **배치 처리** | Batch Processing | 대량의 데이터를 개별 처리하지 않고 하나의 작업 단위로 묶어 동시에 일괄 처리하는 기법입니다. |
| **캐싱** | Caching | 자주 쓰이거나 이미 계산된 결과값을 저장소에 보관하여 불필요한 재계산을 생략하는 방식입니다. |
