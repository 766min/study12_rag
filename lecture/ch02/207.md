### 2.1 통합 파이프라인의 구조

<aside>

- **개별 실행의 한계**: 단계별 코드를 수동으로 실행하면 작업 누락 및 데이터 불일치가 발생합니다.
- **파이프라인 결합**: 입력 경로(Path)만 전달하면 데이터 전처리부터 벡터 DB 저장까지 자동으로 완료됩니다.
</aside>

### 2.2 PGVector 저장소 초기화 실습

<aside>

```python
import os
from dotenv import load_dotenv
from langchain_openai import OpenAIEmbeddings
from langchain_postgres.vectorstores import PGVector

load_dotenv()

embeddings_model = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

# 데이터베이스 연결 URL을 가져옵니다.
connection_url = os.getenv("DATABASE_URL")

# PGVector 벡터 저장소 인스턴스를 생성합니다.
vector_store = PGVector(
    embeddings=embeddings_model,
    collection_name="integrated_university_rules",
    connection=connection_url,
    use_jsonb=True # 메타데이터를 빠른 조회가 가능한 JSONB 형태로 저장
)

print("PGVector 인스턴스 초기화 완료")
```

## 3. SQLRecordManager를 활용한 증분 갱신(Incremental Indexing)

<aside>
💡

<u>**증분 갱신**</u>
기존 저장소의 문서 해시값을 비교하여 신규 추가되거나 변경된 문서만 선별하여 저장하는 기술

</aside>

### 3.1 증분 갱신(Incremental Indexing)의 동작 원리

<aside>

- **전체 재색인의 문제**: 기존 문서를 매번 전체 재저장하면 API 비용이 지속해서 청구되고 DB 입출력 병목이 발생합니다.
- **SQLRecordManager**: 문서의 출처(Source)와 내용의 해시(Hash) 값을 기록하는 일종의 '작업 장부'입니다.
- **index() 함수**: 장부를 조회하여 새로 생성된 청크는 추가(add), 수정된 청크는 업데이트(update), 변경이 없는 청크는 건너뜁니다(skip).
</aside>

### 3.2 레코드 매니저 초기화 및 1차 인덱싱 실습

<aside>

장부 테이블을 생성하고 초기 규정 문서 2건을 인덱싱합니다.

```python
from langchain_classic.indexes import SQLRecordManager, index
from langchain_core.documents import Document

# 문서 인덱싱 기록을 추적할 장부(RecordManager)를 생성합니다.
namespace = "pgvector/integrated_university_rules"
record_manager = SQLRecordManager(
    namespace=namespace,
    db_url=connection_url
)

# 데이터베이스 내부에 추적용 테이블 스키마를 생성합니다.
record_manager.create_schema()

# 1차 등록 대상 문서 (2026 규정 및 장학 규정)
initial_documents = [
    Document(
        page_content="[도서관 규정] 학부생은 최대 5권까지 14일간 대출 가능합니다.",
        metadata={"source": "rules_library.txt", "category": "library", "year": 2026}
    ),
    Document(
        page_content="[장학금 규정] 직전 학기 평점 3.5 이상 시 장학금 대상입니다.",
        metadata={"source": "rules_scholarship.txt", "category": "scholarship", "year": 2026}
    )
]

# cleanup='incremental' 옵션을 적용하여 인덱싱을 실행합니다.
first_index_result = index(
    docs_source=initial_documents,
    record_manager=record_manager,
    vector_store=vector_store,
    cleanup="incremental",
    source_id_key="source" # 중복 여부를 판별하는 기준 메타데이터 키
)

print("=== [1차 인덱싱 결과] ===")
print(first_index_result)
```

### 3.3 내용 변경 감지 및 건너뛰기(Skipped) 검증

<aside>

기존 도서관 규정은 개정하고(수정), 장학 규정은 그대로 둔 채(유지) 다시 인덱싱합니다.

```python
# 수정된 문서 목록: 도서관 규정 개정 및 장학 규정 동일 유지
updated_documents = [
    Document(
        page_content="[개정 도서관 규정] 학부생은 최대 7권까지 21일간 대출 가능합니다.", # 내용 변경
        metadata={"source": "rules_library.txt", "category": "library", "year": 2027}
    ),
    Document(
        page_content="[장학금 규정] 직전 학기 평점 3.5 이상 시 장학금 대상입니다.",       # 기존과 동일
        metadata={"source": "rules_scholarship.txt", "category": "scholarship", "year": 2026}
    )
]

# 2차 인덱싱을 실행합니다.
second_index_result = index(
    docs_source=updated_documents,
    record_manager=record_manager,
    vector_store=vector_store,
    cleanup="incremental",
    source_id_key="source"
)

print("=== [2차 증분 인덱싱 결과] ===")
print(second_index_result)
```

```
=== [2차 증분 인덱싱 결과] ===
{'num_added': 1, 'num_updated': 0, 'num_skipped': 1, 'num_deleted': 1}
```

변경된 도서관 문서는 기존 내용 삭제(1) 후 추가(1) 처리되며, 동일한 장학금 문서는 건너뜁니다(1).

## 4. 인덱싱 검증 및 LLM 모델 연동 질의응답

<aside>
💡

### 4.1 갱신된 벡터 저장소 유사도 검색

<aside>

최신 규정만 검색되는지 확인합니다.

```python
user_query = "학부생 도서 대출 권수와 기간을 알려주세요."

# 유사도 검색 실행 (가장 유사한 문서 1건 추출)
search_results = vector_store.similarity_search(query=user_query, k=1)
retrieved_doc = search_results[0]

print("=== [검색된 최신 문서] ===")
print(f"본문: {retrieved_doc.page_content}")
print(f"메타데이터: {retrieved_doc.metadata}")
```

### 4.2 LLM 모델 연결 및 체인 실행

<aside>

```python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

model = init_chat_model(
    model_provider="openai",
    model="gpt-5-mini",
    temperature=0
)

prompt = ChatPromptTemplate.from_messages([
    ("system", (
        "당신은 대학 학사 규정 안내 도우미입니다.\n"
        "제공된 [참고 문서]에만 근거하여 답변하고, 문서에 없는 내용은 지어내지 마세요.\n\n"
        "[참고 문서]:\n{context}"
    )),
    ("user", "{question}")
])

chain = prompt | model | StrOutputParser()

response = chain.invoke({
    "context": retrieved_doc.page_content,
    "question": user_query
})

print("=== [생성 답변] ===")
print(response)
```

```
=== [생성 답변] ===
학부생은 도서를 최대 7권까지, 대출 기간은 21일입니다.
```

| **증분 갱신** | Incremental Indexing | 전체 데이터를 다시 넣지 않고, 신규 또는 수정된 데이터만 골라 업데이트하는 방식입니다. |
| **레코드 매니저** | Record Manager | 어떤 문서가 언제 어떤 내용으로 저장되었는지 출석부처럼 이력을 추적하는 관리 도구입니다. |
| **네임스페이스** | Namespace | 데이터베이스 내에서 특정 벡터 저장소 컬렉션의 기록을 구분 짓는 고유한 이름표입니다. |
| **해시값** | Hash Value | 문서 내용이 조금이라도 바뀌었는지 1초 만에 감지하기 위해 텍스트를 고유한 문자열로 변환한 값입니다. |
