<aside>

```bash

  --name postgres \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgress \
  -e POSTGRES_DB=postgress \
  -p 5432:5432 \
```

## 2. PostgreSQL + pgvector의 원리

<aside>
💡

<u>**pgvector 확장은 전통적인 관계형 데이터베이스에 다차원 숫자 배열(벡터)을 저장하고 연산하는 기능을 부여합니다.**</u>
일반 회원 정보, 결제 내역과 같은 일반 테이블 데이터와 임베딩 벡터 데이터를 단 하나의 데이터베이스 안에서 통합 관리할 수 있습니다.

</aside>

### 2.1 관계형 DB와 벡터 확장의 결합

<aside>

- **통합 관리**: 별도의 전용 벡터 DB를 운영할 필요 없이 기존 데이터 인프라 안에서 벡터를 안전하게 다룹니다.
- **트랜잭션 보장**: 데이터의 일관성과 무결성을 보장하는 데이터베이스 고유의 안정성을 유지합니다.
</aside>

### 2.2 컬렉션(Collection)과 테이블 분리 구조

<aside>

- **컬렉션 메타데이터**: LangChain은 DB 내부에서 컬렉션 정보를 `langchain_pg_collection` 테이블로 관리합니다.
- **임베딩 데이터 적재**: 실제 본문 텍스트와 벡터 좌표값은 `langchain_pg_embedding` 테이블에 저장되어 관리됩니다.
</aside>

## 3. LangChain을 활용한 벡터DB 저장(Upsert) 실습

<aside>
💡

LangChain의 PGVector 모듈을 활용해 PostgreSQL(pgvector)과 연동하고, 문서 청크를 벡터 데이터로 변환해 저장합니다. 개발자가 임베딩을 일일이 수동 연산할 필요 없이 텍스트 객체만 넘겨주면, 모듈 내부에서 바인딩된 임베딩 모델을 자동으로 호출하여 데이터베이스에 배치(Batch) 단위로 일괄 적재합니다.

</aside>

### 3.1 DB 연결 및 PGVector 인스턴스 초기화

<aside>

환경 변수에서 로드한 DB URL을 바탕으로 PGVector 저장소를 초기화합니다.

```python
import os
from dotenv import load_dotenv
from langchain_openai import OpenAIEmbeddings
from langchain_postgres.vectorstores import PGVector

load_dotenv()

embeddings_model = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

# 데이터베이스 접속 URL을 가져옵니다.
connection_url = os.getenv("DATABASE_URL")

# PGVector 인스턴스를 초기화합니다.
vector_store = PGVector(
    embeddings=embeddings_model,    # 임베딩 생성 모델 연결
    collection_name="library_rules",    # 보관할 컬렉션 테이블 식별자
    connection=connection_url,  # PostgreSQL 연결 문자열
    use_jsonb=True  # 메타데이터를 효율적인 JSONB 형태로 저장
)

print("PostgreSQL + pgvector 연결 및 초기화 완료")
```

```
PostgreSQL + pgvector 연결 및 초기화 완료
```

</aside>

### 3.2 문서 청크 일괄 저장(Upsert)

<aside>

- **add_texts**: 텍스트 조각들을 전달하여 임베딩 연산과 데이터베이스 적재를 한 번에 실행합니다.
- **고유 식별자(ID) 부여**: 각 청크에 식별자를 부여하여 데이터 중복 적재를 방지하고 업데이트를 처리합니다.

```python
# 저장할 도서관 규정 청크 리스트를 정의합니다.
library_rule_chunks = [
    "[2026학년도 중앙도서관 대출 및 열람 규정]\n제1조(대출자격) 본교 재학생 및 휴학생은 학생증을 제시한 후 도서를 대출할 수 있습니다.",
    "제2조(대출 권수 및 기간) 학부생은 1인당 최대 5권까지 대출할 수 있으며 대출 기간은 14일입니다.\n단, 학술 연구용 특수 도서는 7일간 대출 가능하며 연장은 불가능합니다.",
    "제3조(연체 및 제재) 반납 기한을 초과할 경우 연체 일수만큼 대출이 정지됩니다."
]

# 청크별 고유 식별자 ID를 정의합니다.
chunk_ids = ["rule_chunk_001", "rule_chunk_002", "rule_chunk_003"]

# PostgreSQL 데이터베이스에 청크와 임베딩을 저장(Upsert)합니다.
saved_ids = vector_store.add_texts(
    texts=library_rule_chunks,
    ids=chunk_ids
)

# 적재된 청크 ID 결과를 확인합니다.
print(f"DB에 저장 완료된 청크 개수: {len(saved_ids)}개")
print(f"저장된 청크 ID 목록: {saved_ids}")
```

```
DB에 저장 완료된 청크 개수: 3개
저장된 청크 ID 목록: ['rule_chunk_001', 'rule_chunk_002', 'rule_chunk_003']
```

## 4. 벡터 검색 및 LLM 모델 연동 질의응답 실습

<aside>
💡

PostgreSQL(pgvector) 내부의 벡터 거리 연산 기능을 활용해 사용자의 질문과 가장 유사한 문서를 빠르게 찾아내고, 이를 LLM 모델에 전달하여 완성도 높은 답변을 도출합니다. 복잡한 SQL 쿼리나 검색 연산 로직을 직접 짤 필요 없이, LangChain의 표준 인터페이스를 통해 단 몇 줄의 코드만으로 간결한 RAG 체인을 구현합니다.

</aside>

### 4.1 벡터 유사도 검색 실행

<aside>

**similarity_search**: 사용자 질의를 실시간으로 임베딩한 후, DB 내 벡터 컬럼과의 거리를 계산해 최적의 문서를 추출합니다.

```python
# 사용자 질문을 정의합니다.
question = "특수 도서는 며칠 동안 대출할 수 있나요?"

# PostgreSQL 벡터DB에서 가장 관련성이 높은 청크 1개를 검색합니다.
search_results = vector_store.similarity_search(
    query=question,
    k=1 # 가장 유사도가 높은 청크 1개 반환
)

# 검색된 최적 청크의 본문을 추출합니다.
retrieved_context = search_results[0].page_content
print("=== [PostgreSQL 벡터 검색 결과] ===")
print(retrieved_context)
```

```
=== [PostgreSQL 벡터 검색 결과] ===
제2조(대출 권수 및 기간) 학부생은 1인당 최대 5권까지 대출할 수 있으며 대출 기간은 14일입니다.
단, 학술 연구용 특수 도서는 7일간 대출 가능하며 연장은 불가능합니다.
```

</aside>

### 4.2 LLM 모델 연결 및 최종 체인 실행

<aside>

```python
from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

model = init_chat_model(
    model_provider="openai",
    model="gpt-5-mini",
    temperature=0
)

# 검색 문맥 주입용 프롬프트를 정의합니다.
qa_prompt = ChatPromptTemplate.from_messages([
    ("system", (
        "당신은 대학 도서관 규정 안내원입니다.\n"
        "제공된 [참고 청크]의 내용에만 엄격히 근거하여 질문에 답변하세요.\n"
        "내용에 언급되지 않은 사실은 절대 지어내지 마세요.\n\n"
        "[참고 청크]:\n{context}"
    )),
    ("user", "{question}")
])

# RAG 파이프라인 체인을 구성합니다.
rag_chain = qa_prompt | model | StrOutputParser()

# 검색된 문서와 질문을 주입하여 답변을 생성합니다.
response = rag_chain.invoke({
    "context": retrieved_context,
    "question": question
})

print("=== [최종 답변] ===")
print(response)
```

```
=== [최종 답변] ===
학술 연구용 특수 도서는 7일간 대출할 수 있으며, 연장은 불가능합니다.
```

### 3.2 개념 요약 키워드

- **PostgreSQL + pgvector**: 전통적인 관계형 데이터와 고차원 벡터 임베딩을 하나의 시스템에서 다루는 통합 저장소.
- **Docker 기반 배포**: 명령어 한 줄로 pgvector가 내장된 데이터베이스 인스턴스를 격리 생성하는 가상화 기술.
- **DBeaver Extension 활성화**: `CREATE EXTENSION vector;` 명령어로 DB 내부에 벡터 데이터 조작 기능을 켜는 절차.

### 3.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **피지벡터** | pgvector | PostgreSQL에서 벡터 임베딩을 저장하고 거리 연산 검색을 수행할 수 있도록 지원하는 공식 확장 모듈입니다. |
| **도커** | Docker | 애플리케이션과 실행 환경(DB, OS 설정 등)을 하나의 가벼운 컨테이너로 묶어 어디서나 동일하게 실행해 주는 플랫폼입니다. |
| **디비버** | DBeaver | 데이터베이스 내부의 테이블, 데이터, 확장을 시각적으로 확인하고 SQL을 실행할 수 있는 범용 DB 관리 도구입니다. |
| **업서트** | Upsert | 신규 데이터는 삽입(Insert)하고, 기존 식별자가 존재하는 데이터는 갱신(Update)하는 병합 저장 동작입니다. |
