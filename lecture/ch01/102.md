## 2. RAG 파이프라인 구조: 인덱싱과 질의

<aside>
💡

<u>**RAG 시스템은 크게 '시험 전 공부하기(인덱싱)'와 '시험 당일 문제 풀기(질의)'라는 두 단계로 나뉩니다.**</u> 방대한 문서를 사전에 효율적인 데이터베이스로 구축해 두어야, 사용자의 실시간 질문에 지체 없이 정확한 답변을 제공할 수 있습니다.

</aside>

### 2.1 인덱싱(Indexing) vs 질의(Query) 단계

<aside>

<u>**인덱싱 단계 (사전 준비 작업)**</u>

<aside>
질문을 받기 전에 외부 문서를 수집하고, 쪼개고, 숫자로 변환하여 검색 가능한 저장소에 저장하는 과정입니다.

</aside>

<u>**질의 단계 (실시간 실행 작업)**</u>

<aside>
사용자가 질문을 입력하면 가장 관련성 높은 문서를 찾아내어 모델에 전달하고, 최종 답변을 생성하는 과정입니다.

</aside>

| **구분** | **인덱싱 단계 (Indexing)** | **질의 단계 (Query)** |
| --- | --- | --- |
| **작업 시점** | 사용자의 질문이 발생하기 전 (배치/사전 작업) | 사용자가 질문을 입력한 즉시 (실시간 작업) |
| **포함 단계** | 1단계 수집 $\rightarrow$2단계 분할 $\rightarrow$ 3단계 임베딩·저장 | 4단계 검색 $\rightarrow$ 5단계 생성 |
| **비유** | 시험 치기 전 참고서를 읽고 요약 노트를 만들어 두는 과정 | 시험 문제를 읽고 요약 노트에서 답을 찾아 서술하는 과정 |
</aside>

## 3. RAG 5단계 핵심 흐름

<aside>
💡

<u>**RAG는 수집, 분할, 임베딩, 검색, 생성의 5단계를 거쳐 정확한 사실 기반의 답변을 완성합니다.**</u> 각 단계는 파이프라인처럼 유기적으로 연결되어, 앞 단계의 결과물이 다음 단계의 입력값으로 이어집니다.

</aside>

### 3.1 인덱싱 파이프라인 실습 (수집, 분할, 임베딩)

<aside>

<u>**1단계: 문서 수집 (Loading)**</u>

<aside>
PDF, 웹페이지, 내부 데이터베이스 등 다양한 형식의 원본 데이터를 파이썬이 다룰 수 있는 텍스트로 추출합니다.

</aside>

**<u>2단계: 문서 분할 (Chunking)</u>**

<aside>
긴 문서를 인공지능이 한 번에 이해하기 좋은 작은 단위(청크, Chunk)로 자릅니다.

</aside>

**<u>3단계: 임베딩 및 저장 (Embedding & Storing)</u>**

<aside>
분할된 텍스트 조각을 의미 기반의 숫자 배열(벡터)로 변환하여 벡터 데이터베이스에 저장합니다.

</aside>

```python
import os
from dotenv import load_dotenv

# 텍스트를 문맥 단위로 분할해 주는 공식 Splitter 클래스를 불러옵니다.
from langchain_text_splitters import RecursiveCharacterTextSplitter

# 텍스트를 숫자로 변환해 주는 OpenAI 임베딩 클래스를 불러옵니다.
from langchain_openai import OpenAIEmbeddings

# 메모리 상에서 작동하는 벡터 저장소를 불러옵니다.
from langchain_core.vectorstores import InMemoryVectorStore

load_dotenv()

# [1단계: 문서 수집] 학교 규정 원본 문서를 수집했다고 가정합니다.
raw_text = """[스파르타대학교 수강신청 및 성적 장학 규정]
제1조(신청 학점): 학생은 학기당 최소 12학점에서 최대 19학점까지 수강 신청할 수 있습니다.
제2조(초과 신청): 직전 학기 평점 평균이 4.0 이상인 학생은 다음 학기에 최대 21학점까지 신청 가능합니다.
제3조(성적 장학금): 직전 학기 15학점 이상을 이수하고 평점 평균 3.5 이상을 취득한 학생 중 선발합니다.
단, F 학점이 포함된 과목이 있는 경우 성적 장학금 지급 대상에서 제외됩니다."""

# [2단계: 문서 분할] 문맥 단절을 방지하기 위해 겹침 구간(overlap)을 두고 자르는 분할기를 설정합니다.
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=90, # 한 조각(청크)의 최대 글자 수를 90자로 제한합니다.
    chunk_overlap=20 # 앞뒤 조각이 20자씩 겹치도록 설정하여 문맥 유실을 방지합니다.
)

# 원본 텍스트를 설정한 규칙에 따라 여러 개의 Document 객체 리스트로 분할합니다.
split_docs = text_splitter.create_documents([raw_text])

# 분할된 결과물 확인을 위해 청크 개수와 내용을 출력합니다.
print(f"총 {len(split_docs)}개의 청크로 분할되었습니다.\n")
for i, doc in enumerate(split_docs):
    print(f"[청크 {i+1}]: {doc.page_content}\n")

# [3단계: 임베딩 및 저장] 분할된 조각을 숫자로 변환하여 메모리 벡터 저장소에 적재합니다.
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = InMemoryVectorStore.from_documents(
    documents=split_docs,
    embedding=embeddings
)

print("인덱싱 완료: 문서가 임베딩되어 벡터 저장소에 안전하게 보관되었습니다.")

```

```
총 4개의 청크로 분할되었습니다.

[청크 1]: [스파르타대학교 수강신청 및 성적 장학 규정]
제1조(신청 학점): 학생은 학기당 최소 12학점에서 최대 19학점까지 수강 신청할 수 있습니다.

[청크 2]: 제2조(초과 신청): 직전 학기 평점 평균이 4.0 이상인 학생은 다음 학기에 최대 21학점까지 신청 가능합니다.

[청크 3]: 제3조(성적 장학금): 직전 학기 15학점 이상을 이수하고 평점 평균 3.5 이상을 취득한 학생 중 선발합니다.

[청크 4]: 단, F 학점이 포함된 과목이 있는 경우 성적 장학금 지급 대상에서 제외됩니다.

인덱싱 완료: 문서가 임베딩되어 벡터 저장소에 안전하게 보관되었습니다.
```

</aside>

### 3.2 질의 파이프라인 실습 (검색, 생성)

<aside>

<u>**4단계 검색 (Retrieval)**</u>

<aside>
사용자 질문을 기반으로 가장 관련성이 높은 청크를 벡터 유사도 기준으로 찾아옵니다.

</aside>

<u>**5단계 생성 (Generation)**</u>

<aside>
검색된 청크를 프롬프트의 문맥(`context`)으로 주입하여 모델이 사실에 입각해 답하도록 유도합니다.

</aside>

```python
# 언어 모델 초기화 함수와 프롬프트 템플릿, 문자열 파서를 불러옵니다.
from langchain.chat_models import init_chat_model
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 사용자의 실제 질문을 정의합니다.
user_query = "직전 학기 성적이 4.1점인데 다음 학기에 최대 몇 학점까지 신청할 수 있나요?"

# [4단계: 검색] 저장소에서 질문과 가장 유사한 상위 1개의 청크(k=1)를 찾아옵니다.
retriever = vector_store.as_retriever(search_kwargs={"k": 1})
retrieved_results = retriever.invoke(user_query)

# 검색된 문서 조각의 내용을 텍스트 형태로 추출합니다.
context_chunk = retrieved_results[0].page_content
print("=== [4단계: 검색된 근거 청크] ===")
print(context_chunk)

# [5단계: 생성] 모델을 초기화하고 사실 기반 답변을 위해 temperature를 0으로 설정합니다.
llm = init_chat_model(
    model_provider="openai",
    model="gpt-5-mini",
    temperature=0
)

# 검색된 문맥({context})과 사용자의 질문({question})을 결합하는 프롬프트를 구성합니다.
prompt_template = ChatPromptTemplate.from_messages([
    ("system", "제공된 [참고 문서]의 내용에만 근거하여 정확하게 답변하세요.\n\n[참고 문서]:\n{context}"),
    ("user", "{question}")
])

# 프롬프트 -> 모델 -> 문자열 파서로 이어지는 RAG 체인을 조립합니다.
pipeline_chain = prompt_template | llm | StrOutputParser()

# 문맥과 질문을 전달하여 최종 답변을 생성합니다.
final_response = pipeline_chain.invoke({
    "context": context_chunk,
    "question": user_query
})

print("\n=== [5단계: 최종 생성된 답변] ===")
print(final_response)

```

```
=== [4단계: 검색된 근거 청크] ===
제2조(초과 신청): 직전 학기 평점 평균이 4.0 이상인 학생은 다음 학기에 최대 21학점까지 신청 가능합니다.

=== [5단계: 최종 생성된 답변] ===
직전 학기 평점이 4.1점이므로, 제2조에 따라 다음 학기에 최대 21학점까지 신청할 수 있습니다.
```

## 4. 단계별 품질 병목 지점 분석

<aside>
💡

<u>**파이프라인 중 어느 한 단계라도 어긋나면 최종 답변의 품질과 신뢰도는 크게 떨어집니다.**</u> 따라서 AI 답변에 오류가 발생했을 때는 5단계 중 구체적으로 어느 지점에서 결함이 생겼는지 체계적으로 추적하고 진단해야 합니다.

</aside>

### 4.1 단계별 주요 병목 현상 및 영향

<aside>

<u>**수집 단계 결함**</u>

<aside>
표가 깨져 있거나 글자가 누락된 상태로 읽어오면 모든 후속 단계가 잘못된 데이터를 다루게 됩니다.

</aside>

<u>**분할 단계 결함**</u>

<aside>
문맥을 고려하지 않고 단순 길이로 자르면 문장 중간이 끊겨 의미 파악이 불가능해집니다.

</aside>

**<u>임베딩 단계 결함</u>**

<aside>
단어의 의미적 유사성을 올바르게 계산하지 못해 엉뚱한 거리 값이 도출됩니다.

</aside>

**<u>검색 단계 결함</u>**

<aside>
질문의 의도와 동떨어진 관련 없는 청크가 전달되어 모델에 잘못된 참고서가 들어갑니다.

</aside>

**<u>생성 단계 결함</u>**

<aside>
정확한 참고 문서를 넘겨주었음에도 모델이 주어진 문서를 무시하고 지어낸 답변(환각)을 출력합니다.

</aside>

| **단계** | **주요 병목 원인** | **최종 결과에 미치는 영향** |
| --- | --- | --- |
| **1. 문서 수집** | 스캔본 인식 오류, 표/서식 깨짐 | 왜곡된 데이터가 시스템 전체로 전파 |
| **2. 문서 분할** | 청크 크기 과소/과대, 문맥 단절 | 주어·목적어 유실로 핵심 정보 손실 |
| **3. 임베딩** | 도메인 특화 용어 의미 반영 실패 | 질문과 문서 조각 간의 의미 매칭 실패 |
| **4. 검색** | 저품질 청크 검색, 검색 개수($k$) 부족 | 모델에게 잘못된 참고 자료 전달 |
| **5. 생성** | 프롬프트 지시 불이행, 환각 현상 | 제공된 근거를 무시한 거짓 답변 생성 |
</aside>

### 5.2 개념 요약 키워드

- **인덱싱(Indexing)**: 질문에 앞서 문서를 수집·분할·임베딩하여 저장하는 사전 구축 작업
- **질의(Query)**: 질문을 받아 유사한 청크를 검색하고 최종 답변을 생성하는 실시간 실행 작업
- **청크 오버랩(Chunk Overlap)**: 텍스트 분할 시 문맥 단절을 방지하기 위해 인접한 조각 사이에 겹치도록 설정하는 여유 구간

### 3.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **청크** | Chunk | 긴 문서를 검색하기 용이하도록 일정한 규칙에 따라 분할한 텍스트 조각 |
| **텍스트 분할기** | Text Splitter | 원본 문서를 지정된 크기와 중복 구간에 맞춰 청크로 잘라주는 전용 도구 |
| **임베딩** | Embedding | 컴퓨터가 문장의 의미를 이해할 수 있도록 텍스트를 고차원 숫자 배열(벡터)로 변환하는 기술 |
| **벡터 저장소** | Vector Store | 임베딩된 벡터 데이터를 보관하고 질문과의 유사도를 빠르게 계산하는 특수 저장소 |
| **리트리버** | Retriever | 주어진 질문에 대해 벡터 저장소에서 연관성이 가장 높은 문서 청크를 가져오는 검색기 |
