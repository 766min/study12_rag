## 2. Re-ranking의 원리와 2단계 검색 구조

<aside>
💡

<u>**Re-ranking(재정렬)**</u>
Re-ranking(재정렬)은 1차로 빠르게 건져낸 문서 후보군을 정밀하게 다시 채점하여 상위권으로 재배치하는 기술입니다.

</aside>

### 2.1 2단계 검색(2-Stage Search)의 흐름

<aside>

<u>**1단계 (Retrieval - 빠른 추출)**</u>

- 수만 건 이상의 방대한 데이터베이스에서 관련 가능성이 있는 상위 문서(Top-N, 보통 10~30개)를 빠르게 수집합니다.
- 검색 속도를 위해 이전 강에서 배운 키워드 검색, 벡터 검색, 혹은 하이브리드 검색을 사용합니다.

<u>**2단계 (Re-ranking - 정밀 재배열)**</u>

- 1단계에서 건져 올린 소수 문서만을 대상으로 질문과 문서의 문맥을 1:1로 정밀 대조합니다.
- 가장 연관성이 높은 최종 상위 문서(Top-K, 보통 2~5개)를 최상단에 재배치합니다.
</aside>

### 2.2 Bi-Encoder vs Cross-Encoder

<aside>

<u>**Bi-Encoder (1차 검색 모델)**</u>

- 질문과 문서를 각각 독립된 숫자 벡터로 변환한 후 각도(유사도)만 비교합니다.
- 계산 속도가 매우 빨라 수백만 개의 문서를 순식간에 훑을 수 있지만, 문맥의 세밀한 상호작용을 놓칠 수 있습니다.

<u>**Cross-Encoder (재정렬 모델)**</u>

- 질문과 문서를 하나의 쌍(`[질문 + 문서]`)으로 묶어 신경망에 동시에 통과시킵니다.
- 질문의 단어들과 문서의 단어들이 서로 어떤 관계를 맺는지 깊이 있게 분석하므로 정확도가 매우 높습니다.
- 연산량이 많아 속도가 느리므로 1차 검색으로 추려낸 소수의 문서에만 적용합니다.
</aside>

## 3. 코드로 보는 Re-ranking과 답변 생성

<aside>
💡

Cross-Encoder로 1차 검색 문서를 재정렬하고, 선별된 핵심 문맥을 LLM 모델에 전달하여 최종 답변을 생성합니다.

</aside>

### 3.1 Cross-Encoder 모델을 활용한 문서 재정렬

<aside>

1차 검색을 통해 3개의 문서 후보가 수집되었다고 가정하고, 순위를 다시 매기는 코드를 작성합니다.

```python
from sentence_transformers import CrossEncoder

# 1차 검색으로 건져온 가상의 문서 리스트 준비
documents = [
    "애플의 새로운 스마트폰 아이폰 15가 출시되었습니다.",
    "사과는 껍질이 붉고 단단하며 당도가 높은 것이 맛있습니다.",
    "삼성전자의 갤럭시 S24는 온디바이스 AI 기능이 뛰어납니다."
]

# 사용자의 실제 질문 정의
query = "맛있는 사과를 고르는 요령이 궁금해요"

# 질문과 문서를 1:1 쌍으로 결합
# Cross-Encoder는 질문과 문서를 한 번에 입력받아 분석합니다.
sentence_pairs = [[query, doc] for doc in documents]

# 연관성 평가 전용 경량 Cross-Encoder 모델 로드
reranker_model = CrossEncoder("Dongjin-kr/ko-reranker")

# 각 문서 쌍의 연관성 점수 계산 (점수가 높을수록 밀접함)
scores = reranker_model.predict(sentence_pairs)

# 점수를 기준으로 내림차순(높은 순) 정렬
ranked_results = sorted(
    zip(documents, scores),
    key=lambda x: x[1],
    reverse=True
)

# 재정렬 결과 확인
print(f"질문: {query}\n")
print("[Re-ranking 순위 결과]")
for idx, (doc, score) in enumerate(ranked_results):
    print(f"{idx + 1}위 (점수: {score:.4f}): {doc}")
```

```
질문: 맛있는 사과를 고르는 요령이 궁금해요

[Re-ranking 순위 결과]
1위 (점수: 0.1274): 사과는 껍질이 붉고 단단하며 당도가 높은 것이 맛있습니다.
2위 (점수: 0.0001): 애플의 새로운 스마트폰 아이폰 15가 출시되었습니다.
3위 (점수: 0.0001): 삼성전자의 갤럭시 S24는 온디바이스 AI 기능이 뛰어납니다.
```

</aside>

### 3.2 재정렬된 문맥 주입 및 LLM 모델 답변 생성

<aside>

재정렬 결과 1위로 선정된 가장 정확한 문서를 문맥으로 채택하여 LLM 모델에 전달합니다.   

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# 재정렬된 문서 중 최상위(1위) 문서를 문맥(Context)으로 채택
top_doc = ranked_results[0][0]

# 언어 모델에 전달할 프롬프트 구성
prompt = f"""다음 문서를 참고하여 질문에 명확하고 친절하게 답변하세요.

[참고 문서]
{top_doc}

[질문]
{query}"""

# LLM 모델 추론 실행
response = model.invoke(prompt)

# 최종 결과 출력
print("\n[최종 생성 답변]")
print(response.content)
```

```

[최종 생성 답변]
좋은 질문이에요 — 참고 문서에도 나오듯이 “껍질이 붉고 단단하며 당도가 높은 것”이 맛있는 사과입니다. 이를 바탕으로 시장이나 마트에서 실전으로 골라볼 수 있는 구체적인 요령을 정리해 드릴게요.

골라야 할 조건(간단히)
- 껍질 색: 전체적으로 선명한 붉은색(품종에 따라 차이가 있으니 아래 설명 참고). 
- 단단함: 손으로 눌렀을 때 단단하고 탄력이 있는 것(말랑하면 과숙).
- 당도(맛): 향이 좋고 무게 대비 단단한 느낌이면 대체로 당도가 높음.

장보기 팁(실전)
- 겉모양 확인: 반점·갈라짐·멍이나 흠집이 없는지 확인하세요. 흠집이 심하면 내부가 상했을 가능성.
- 무게 감별: 같은 크기면 손에 들었을 때 묵직한 쪽이 속이 차 있고 즙이 많아 달콤할 확률이 큽니다.
- 냄새 맡기: 꼭지는 떼지 말고(상처가 생기면 상하기 쉬움) 과일 아래쪽을 살짝 맡아 향이 풍부한 것이 당도가 높은 경우가 많습니다.
- 촉감 검사: 엄지로 가볍게 눌러 탄력이 있는지 확인하세요. 너무 말랑하면 과숙, 너무 딱딱하면 덜 익음(단, 많은 사과는 단단한 게 좋습니다).
- 꼭지와 받침부: 꼭지가 말랑말랑하거나 빠져 있으면 오래된 것일 수 있습니다. 꼭지가 튼튼한 편이 신선합니다.

품종/예외 사항
- 참고 문서의 “붉은 껍질” 기준은 많은 인기 품종(후지·갤라 등)에 해당합니다. 그러나 그랜니 스미스처럼 초록색 품종은 원래 색이 다르므로 색만으로 판단하지 마세요. 품종별 특성을 알고 고르는 것이 좋습니다(예: 후지는 달고 아삭, 그랜니는 새콤함).

간단한 보관 팁
- 냉장 보관하면 신선도와 단맛 유지에 도움됩니다(김치칸이나 과일칸).
- 상온에 두면 빠르게 물러질 수 있으니 며칠 내에 먹을 양만 상온 보관하세요.

요약
- 문서대로: 껍질이 붉고 단단하며(향과 무게로) 당도가 높은 사과를 고르세요.
- 추가로 겉상태·무게·냄새·촉감도 확인하면 실패 확률이 낮습니다.

필요하면 자주 가는 마트나 시장에서 많이 보는 품종별 특징(후지·갤라·하니크리스프·그랜니 등)도 정리해 드릴게요. 어떤 걸 자주 드시나요?
```

### 4.2 개념 요약 키워드

- **재정렬 (Re-ranking)**: 1차 검색기로 건져낸 문서 후보를 정밀 채점하여 우선순위를 다시 결정하는 RAG 최적화 기술.
- **크로스 인코더 (Cross-Encoder)**: 질문과 문서를 한 번에 입력받아 둘 사이의 문맥적 연관도를 정밀하게 점수화하는 AI 모델.
- **2단계 검색 (2-Stage Search)**: '빠른 탐색(Bi-Encoder/하이브리드)'과 '정밀 검수(Cross-Encoder)'로 속도와 정확도를 모두 잡는 검색 아키텍처.

### 4.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **재정렬** | Re-ranking | 1차 검색된 여러 문서의 연관도를 정밀 재평가하여 최적의 순서로 다시 나열하는 기법 |
| **크로스 인코더** | Cross-Encoder | 질문과 문서를 함께 읽어 단어 간의 상호작용과 문맥을 깊이 있게 채점하는 신경망 모델 |
| **바이 인코더** | Bi-Encoder | 질문과 문서를 따로따로 벡터로 변환하여 거리를 빠르게 계산하는 모델 (1차 검색용) |
| **2단계 검색** | 2-Stage Search | 대규모 검색의 속도를 챙기는 1단계와 소수 문서의 정확도를 챙기는 2단계로 분리된 시스템 |
