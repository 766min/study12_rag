## 2. 검색의 두 가지 핵심 방식

<aside>
💡

<u>**글자 찾기 vs 의미 찾기**</u>
키워드 검색은 글자가 똑같은지(단어 찾기 게임), 벡터 검색은 문장의 속뜻이 같은지(눈치 빠른 친구)를 확인합니다.

</aside>

### 2.1 키워드 검색과 벡터 검색 비교

<aside>

- **키워드 검색 (BM25)**: 사용자가 입력한 단어가 문서에 얼마나 자주 등장하는지 셉니다. '컴퓨터'를 검색하면 'PC'라고 적힌 문서는 찾지 못합니다.
- **벡터 검색 (Semantic Search)**: 문장을 숫자(벡터)로 바꾼 뒤, 의미가 가장 유사한 문서를 찾습니다. "우울할 때 읽기 좋은 책"이라고 치면 '우울'이라는 단어가 없어도 위로가 되는 책을 찾아줍니다.
</aside>

## 3. 코드로 보는 검색 방식의 차이

<aside>

실제로 두 검색 방식이 어떻게 다른 결과를 내는지, 그리고 LLM 모델을 어떻게 불러오는지 확인해 봅니다.

```python
import os
from dotenv import load_dotenv
from rank_bm25 import BM25Okapi
from langchain_openai import OpenAIEmbeddings
from langchain.chat_models import init_chat_model
import numpy as np

load_dotenv()

# 우리가 검색할 대상이 되는 3개의 가상 문서 리스트입니다.
documents = [
    "애플의 새로운 스마트폰 아이폰 15가 출시되었습니다.",
    "삼성전자의 갤럭시 S24는 AI 기능이 뛰어납니다.",
    "현대자동차의 전기차 아이오닉은 연비가 훌륭합니다."
]

# ---------------------------------------------------------
# [1] 키워드 검색 (BM25) 준비
# ---------------------------------------------------------
# 문서를 띄어쓰기 기준으로 쪼개어 단어 리스트로 만듭니다.
tokenized_docs = [doc.split(" ") for doc in documents]
bm25 = BM25Okapi(tokenized_docs)

# ---------------------------------------------------------
# [2] 벡터 검색 준비 및 gpt-5-mini 모델 선언
# ---------------------------------------------------------
# 의미 검색을 위해 문장을 숫자로 바꾸는 임베딩 모델입니다.
embeddings_model = OpenAIEmbeddings(model="text-embedding-3-small")
doc_vectors = embeddings_model.embed_documents(documents)

model = init_chat_model(
    model_provider="openai",
    model="gpt-5-mini",
    temperature=0
)

# ---------------------------------------------------------
# [3] 검색 실행 및 비교
# ---------------------------------------------------------
# 검색어 (아이폰이라는 정확한 단어가 없습니다)
query = "사과 모양 로고가 있는 휴대폰"
print(f"질문: {query}\n")

# --- 키워드 검색 결과 ---
tokenized_query = query.split(" ")
bm25_scores = bm25.get_scores(tokenized_query)
best_bm25_index = np.argmax(bm25_scores)

print("[키워드 검색 1위 문서]")
print(documents[best_bm25_index])
# 엉뚱한 결과가 나옵니다. ('사과', '로고'라는 글자가 없기 때문)

# --- 벡터 검색 결과 ---
query_vector = embeddings_model.embed_query(query)
vector_scores = [np.dot(query_vector, doc_vec) for doc_vec in doc_vectors]
best_vector_index = np.argmax(vector_scores)

print("\n[벡터 검색 1위 문서]")
print(documents[best_vector_index]) 
# 정답을 찾습니다. ('사과 모양 휴대폰' = '아이폰' 이라는 의미를 파악)
```

```

[키워드 검색 1위 문서]
애플의 새로운 스마트폰 아이폰 15가 출시되었습니다.

[벡터 검색 1위 문서]
애플의 새로운 스마트폰 아이폰 15가 출시되었습니다.
```

## 4. 개념 체크 하기

### 4.1 개념 확인 문제

<aside>
💡

**Q1. init_chat_model을 사용하여 최신 모델(gpt-5-mini)을 선언할 때, temperature=0으로 설정하는 이유는 무엇인가요?**

---

- [ ]  (1) 인덱싱 속도를 비약적으로 높이기 위해서
- [ ]  (2) 인공지능이 무작위성을 배제하고 제공된 검색 문맥에만 기반하여 엄격하고 일관된 답변을 생성하게 유도하기 위해서
- [ ]  (3) 데이터베이스 접속 권한을 안전하게 관리하기 위해서
- [ ]  (4) 문서 검색 개수를 자동으로 제한하기 위해서

- **답안 설명**
    
    **정답:** 2번
    
    온도를 뜻하는 temperature를 0으로 설정하면, 인공지능이 창의성을 발휘해 없는 말을 지어내는 것을 방지하고 사실 기반의 답변을 하도록 만듭니다.
    
</aside>

**Q2. 다음 중 검색 방식과 적합한 상황이 올바르게 짝지어진 것은?**

---

- [ ]  (1) 키워드 검색 - "어제 본 영화랑 비슷한 분위기의 영화 추천해줘”
- [ ]  (2) 벡터 검색 - "부품 번호 AX-9982 재고 현황”
- [ ]  (3) 키워드 검색 - "특정 부서의 2024년도 예산안 엑셀 파일”
- [ ]  (4) 메타데이터 필터링 - "사과 모양 휴대폰 찾아줘”

- **답안 설명**
    
    **정답:** 3번
    
    정확한 단어(부서명, 연도, 예산안 등)가 포함된 문서를 찾을 때는 키워드 검색이 유리합니다. (1)과 (4)는 의미를 찾는 벡터 검색이, (2)는 정확한 글자를 매칭하는 키워드 검색이 적합합니다.

### 4.2 개념 요약 키워드

- **환경 셋팅과 분기**: 프로젝트 초기화부터 LLM 모델 선언까지의 뼈대를 잡고, 단어를 찾는 **키워드 검색**과 의미를 찾는 **벡터 검색**의 차이를 이해합니다.

### 4.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **키워드 검색** | Keyword Search | 검색한 단어가 문서 안에 글자 그대로 얼마나 많이 포함되어 있는지 세어서 문서를 찾는 방식입니다. |
| **벡터 검색** | Vector Search | 글자가 아닌 문장의 '의미'를 숫자(벡터)로 바꾼 뒤, 의미가 가장 가까운 문서를 찾아내는 방식입니다. |
