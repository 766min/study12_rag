## 2. RAG 평가셋(Evaluation Set) 설계 원칙

<aside>
💡

<u>**평가셋 (Evaluation Set)**</u>
검색 및 생성 시스템의 품질을 객관적으로 채점하기 위해 사전에 구축해 두는 **표준 문제와 모범 답안의 묶음**입니다.

</aside>

### 2.1 평가셋의 3대 핵심 요소

<aside>

RAG 파이프라인을 채점하기 위해서는 세 가지 핵심 데이터가 쌍을 이루어야 합니다.

- **질문 (Question)**: 사용자가 실제로 입력할 법한 자연어 질의입니다.
- **정답 (Ground Truth)**: 해당 질문에 대해 시스템이 최종적으로 답변해야 하는 올바른 기준 텍스트입니다.
- **근거 문서 (Context)**: 정답을 도출하기 위해 검색기가 본문 데이터베이스에서 반드시 찾아내야 하는 원본 문서 청크입니다.
</aside>

### 2.2 LLM 모델 기반 평가셋 생성 실습

<aside>

사내 규정 문서 텍스트로부터 LLM 모델을 호출하여 질문과 모범 정답을 자동으로 추출합니다.

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# 평가셋 생성의 근거가 될 원본 문서(Context)를 정의합니다.
source_context = (
    "원격 근무 지원 규정: 주 2회 재택근무가 가능하며, "
    "원격 근무 당일은 오전 9시까지 사내 메신저 근태 채널에 출근 등록을 완료해야 합니다. "
    "재택근무 지원금은 월 50,000원이 지급됩니다."
)

# 문서 내용을 기반으로 질문과 정답 쌍을 생성하는 프롬프트를 구성합니다.
eval_gen_prompt = PromptTemplate.from_template(
    "당신은 RAG 시스템 평가 데이터를 만드는 데이터 엔지니어입니다.\n"
    "제공된 [근거 문서]만을 바탕으로 사용자가 물어볼 만한 간결한 '질문' 1개와 정확한 '정답' 1개를 만드세요.\n\n"
    "[근거 문서]: {context}\n\n"
    "[출력 형식]:\n"
    "질문: <생성된 질문>\n"
    "정답: <생성된 모범 정답>"
)

# 모델 실행 체인을 구성합니다.
eval_chain = eval_gen_prompt | model | StrOutputParser()

# 체인을 실행하여 평가셋을 생성합니다.
generated_pair = eval_chain.invoke({"context": source_context})

# 생성된 평가 데이터셋 딕셔너리를 구성합니다.
eval_dataset = {
    "context": source_context,
    "generated_data": generated_pair
}

print("=== [LLM 기반 평가셋 생성 결과] ===")
print(eval_dataset["generated_data"])
print(f"기준 근거 문서: {eval_dataset['context']}")
```

```
=== [LLM 기반 평가셋 생성 결과] ===
질문: 주에 몇 회 원격(재택) 근무가 가능하고, 원격 근무 당일 출근 등록은 언제 어디에 해야 하며 지원금은 얼마인가요?
정답: 주 2회 가능. 원격 근무 당일 오전 9시까지 사내 메신저의 근태 채널에 출근 등록을 완료해야 하며, 재택근무 지원금은 월 50,000원입니다.
기준 근거 문서: 원격 근무 지원 규정: 주 2회 재택근무가 가능하며, 원격 근무 당일은 오전 9시까지 사내 메신저 근태 채널에 출근 등록을 완료해야 합니다. 재택근무 지원금은 월 50,000원이 지급됩니다.
```

## 3. 검색 단계 평가 지표(Retrieval Metrics)

<aside>
💡

<u>**검색 지표 (Retrieval Metrics)**</u>
검색기가 전체 데이터베이스에서 **정답 문서를 빠짐없이 가져왔는지, 불필요한 노이즈를 섞어 가져오지 않았는지**를 정량화한 수치입니다.

</aside>

### 3.1 정밀도(Context Precision)와 재현율(Context Recall)

<aside>

검색기의 성능은 가져온 문서와 실제 정답 문서 간의 포함 관계로 계산합니다.

- **정밀도 (Context Precision)**: 검색기가 반환한 문서들 중에서 실제 정답 근거 문서가 차지하는 비율입니다. <u>검색 결과의 순도(Quality)</u>를 나타냅니다.
- **재현율 (Context Recall)**: 전체 데이터베이스에 존재하는 정답 근거 문서 중 검색기가 누락 없이 찾아낸 비율입니다. <u>검색의 포괄 범위(Coverage)</u>를 나타냅니다.
</aside>

### 3.2 조화 평균: F1-Score

<aside>

<u>**정밀도와 재현율의 트레이드오프 (Trade-off)</u>**
정밀도와 재현율은 한쪽을 극단적으로 높이면 다른 쪽이 떨어지는 상충 관계를 가집니다. 검색 범위를 무작정 넓히면 정답을 놓치지 않지만(재현율 상승), 무관한 문서가 대량 포함되어 품질이 저하됩니다(정밀도 하락).

<u>**산술평균 대신 조화평균을 쓰는 이유</u>**
단순 산술평균은 한쪽 지표가 심각하게 낮아도 수치가 양호해 보이는 왜곡이 발생합니다. 조화평균(Harmonic Mean)은 두 값 중 더 작은 값에 큰 가중치를 부여하므로, 두 지표 중 하나라도 0에 가까우면 전체 점수가 급격히 하락하여 모델의 결함을 정확하게 드러냅니다.

<u>**F1-Score 계산 수식**</u>

$$
F_1 = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}
$$

<u>**지표 비교 및 성능 판정 기준**</u>

| **측정 케이스** | **정밀도 (Precision)** | **재현율 (Recall)** | **단순 산술평균** | **F1-Score (조화평균)** | **수치 해석 및 모델 상태** |
| --- | --- | --- | --- | --- | --- |
| **극단적 편향 검색기** | 0.10 | 0.90 | 0.50 | **0.18** | 심각한 정밀도 결함을 감지하여 낮은 점수로 엄격히 판정 |
| **균형 잡힌 검색기** | 0.80 | 0.80 | 0.80 | **0.80** | 두 지표 간 밸런스가 유지되어 높은 종합 성능으로 산출 |
</aside>

### 3.3 검색 지표 자동 산출 실습

<aside>

검색 결과 문서 ID와 기준 정답 문서 ID를 대조하고, 산술평균과 F1-Score의 차이를 비교 출력합니다.

```python
# 시스템이 반드시 검색해야 하는 '정답 근거 문서 ID' 목록을 정의합니다.
ground_truth_doc_ids = {"doc_1", "doc_2", "doc_3"}

# RAG 검색기(Retriever)가 반환한 '검색 결과 문서 ID' 목록을 정의합니다.
# doc_1, doc_2는 일치했으나 doc_3은 누락되었고, 무관한 doc_9가 포함된 상태입니다.
retrieved_doc_ids = {"doc_1", "doc_2", "doc_9"}

# 검색된 문서 중 실제 정답과 일치하는 교집합 문서를 확인합니다.
relevant_retrieved = ground_truth_doc_ids.intersection(retrieved_doc_ids)
hits = len(relevant_retrieved)

# 정밀도(Precision) 계산: 맞춘 문서 수 / 검색기가 반환한 전체 문서 수
precision = hits / len(retrieved_doc_ids) if retrieved_doc_ids else 0.0

# 재현율(Recall) 계산: 맞춘 문서 수 / 찾아야 하는 전체 정답 문서 수
recall = hits / len(ground_truth_doc_ids) if ground_truth_doc_ids else 0.0

# 단순 산술평균 계산
arithmetic_mean = (precision + recall) / 2

# 조화평균 기반 F1-Score 계산
if (precision + recall) > 0:
    f1_score = 2 * (precision * recall) / (precision + recall)
else:
    f1_score = 0.0

# 평가 지표 측정 결과를 콘솔에 출력합니다.
print("=== [검색 파이프라인 지표 측정 결과] ===")
print(f"기준 정답 문서 목록: {ground_truth_doc_ids}")
print(f"실제 검색 문서 목록: {retrieved_doc_ids}")
print(f"일치한 정답 문서: {relevant_retrieved} (총 {hits}개 일치)")
print(f"1. Context Precision (정밀도) : {precision:.4f} ({precision * 100:.1f}%)")
print(f"2. Context Recall    (재현율) : {recall:.4f} ({recall * 100:.1f}%)")
print(f"3. 단순 산술평균              : {arithmetic_mean:.4f}")
print(f"4. F1-Score         (조화평균): {f1_score:.4f}")
```

```
=== [검색 파이프라인 지표 측정 결과] ===
기준 정답 문서 목록: {'doc_1', 'doc_2', 'doc_3'}
실제 검색 문서 목록: {'doc_1', 'doc_2', 'doc_9'}
일치한 정답 문서: {'doc_1', 'doc_2'} (총 2개 일치)
1. Context Precision (정밀도) : 0.6667 (66.7%)
2. Context Recall    (재현율) : 0.6667 (66.7%)
3. 단순 산술평균              : 0.6667
4. F1-Score         (조화평균): 0.6667
```

### 4.2 개념 요약 키워드

- **평가셋 (Evaluation Set)**: 질문, 정답, 근거 문서로 구성되어 RAG 시스템의 성능을 정량 채점하는 기준 데이터셋
- **Context Precision**: 검색기가 가져온 문서 중 실제 유효한 근거 문서가 차지하는 비율(품질 지표)
- **Context Recall**: 시스템이 찾아내야 하는 전체 근거 문서 중 검색기가 놓치지 않고 확보한 비율(포괄성 지표)
- **트레이드오프 (Trade-off)**: 검색 범위를 넓히면 재현율은 오르나 정밀도가 떨어지는 상충 관계
- **F1-Score**: 한쪽 지표의 심각한 결함이 산술평균 착시로 가려지지 않도록 조화평균을 적용한 종합 검색 지표

### 4.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **평가셋** | Evaluation Set | 시스템 성능 검증을 위해 질의, 정답, 근거를 한 세트로 구성한 벤치마크 데이터입니다. |
| **모범 정답** | Ground Truth | 시스템이 도출해야 하는 올바른 기준값으로 사전 검증된 참(True) 레이블 데이터입니다. |
| **정밀도** | Context Precision | 검색기가 반환한 문서들 중 실제 정답과 연관된 문서가 차지하는 비율입니다. |
| **재현율** | Context Recall | 전체 정답 문서 중 검색기가 누락 없이 성공적으로 찾아낸 문서의 비율입니다. |
| **트레이드오프** | Trade-off | 한쪽 지표의 성능을 높이려 할 때 다른 쪽 지표가 필연적으로 저하되는 상충 관계입니다. |
| **조화 평균** | F1-Score | 정밀도와 재현율 중 작은 쪽에 더 민감하게 반응하여 두 지표의 균형점을 엄격하게 측정하는 복합 수치입니다. |
