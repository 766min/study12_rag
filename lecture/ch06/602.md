## 2. 생성 단계 평가 지표 (Generation Metrics)

<aside>
💡

<u>**생성 지표의 정의**</u>
인공지능이 최종 출력한 텍스트가 제공된 문맥에 충실한지, 사용자의 질문 의도를 정확하게 충족했는지 검증하는 척도입니다.

</aside>

### 2.1 사실성 (Faithfulness)

<aside>

- **개념**: 생성된 답변의 모든 내용이 검색기가 가져온 '근거 문서(Context)'에 근거하고 있는지를 평가합니다.
- **측정 목적**: 제공된 문서 밖의 허위 정보를 지어내는 **환각(Hallucination)** 현상을 탐별합니다.
- **판정 기준**: 답변 문장을 개별 주장 단위로 쪼갠 뒤, 근거 문서에서 증명 가능한 문장의 비율로 수치를 도출합니다.
</aside>

### 2.2 답변 관련성 (Answer Relevance)

<aside>

- **개념**: 생성된 답변이 사용자가 입력한 '질문(Question)'의 핵심 의도에 알맞게 반응했는지를 평가합니다.
- **측정 목적**: 정보의 참/거짓 여부와 무관하게 엉뚱한 주제를 이야기하는 동문서답 오류를 검출합니다.
- **판정 기준**: 문법 완성도나 문장 길이가 아닌, 질문에 대한 직접적인 해결책 제공 여부를 평가합니다.
</aside>

### 2.3 LLM 기반 생성 지표 채점 실습

<aside>

LLM 모델을 채점관으로 지정하여 답변의 사실성과 관련성을 자동으로 평가하는 체인을 구성합니다.

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

# 평가 결과의 일관성을 위해 temperature(창의성)를 0으로 고정합니다.
model = init_chat_model(
    model="gpt-5-mini",
    model_provider="openai",
    temperature=0
)

# 채점용 시나리오 데이터를 정의합니다.
sample_question = "도서관 주말 운영 시간과 대출 가능 권수는 어떻게 되나요?"
retrieved_context = "중앙도서관 운영 안내: 주말(토, 일)은 오전 10시부터 오후 5시까지 운영하며, 1인당 최대 5권까지 대출 가능합니다."
generated_answer = "도서관은 주말에 오전 10시부터 오후 5시까지 운영하며, 1인당 최대 10권까지 빌릴 수 있습니다."

# 사실성(Faithfulness) 채점을 위한 프롬프트를 구성합니다.
faithfulness_prompt = PromptTemplate.from_template(
    "당신은 엄격한 생성 지표 채점관입니다.\n"
    "[근거 문서]만을 바탕으로 [생성된 답변]의 사실성을 평가하세요.\n"
    "답변에 문서와 일치하지 않거나 왜곡된 수치/내용이 포함되어 있다면 '불합격',"
    "모든 내용이 문서로 뒷받침된다면 '합격'을 출력하고 이유를 1줄로 명시하세요.\n\n"
    "[근거 문서]: {context}\n"
    "[생성된 답변]: {answer}\n"
    "[출력 형식]:\n"
    "결과: <합격/불합격>\n"
    "사유: <1줄 사유>"
)

# 채점 파이프라인 체인을 연결하고 실행합니다.
eval_chain = faithfulness_prompt | model | StrOutputParser()

eval_result = eval_chain.invoke({
    "context": retrieved_context,
    "answer": generated_answer
})

print("=== [LLM 기반 사실성 평가 결과] ===")
print(eval_result)
```

```
=== [LLM 기반 사실성 평가 결과] ===
결과: 불합격
사유: 주말 운영 시간은 문서와 일치하지만 대출 권수는 문서의 '1인당 최대 5권'과 달리 생성 답변이 '10권'으로 문서와 불일치합니다.
```

</aside>

## 3. RAG 파이프라인 실패 원인 분석

<aside>
💡

<u>**오류 진단의 핵심 원칙**</u>
최종 답변에 문제가 발생했을 때, <u>문서를 가져오지 못한 것(검색 실패)</u>인지 <u>문서를 오독한 것(생성 실패)</u>인지를 분리해야 올바른 튜닝이 가능합니다.

</aside>

### 3.1 검색 실패 vs 생성 실패 구분

<aside>

파이프라인 단계별 오류를 비교하면 다음과 같습니다.

| **구분** | **발생 원인** | **주요 증상** | **개선 방향** |
| --- | --- | --- | --- |
| **검색 실패 (Retrieval Failure)** | 청킹 전략 오류, 임베딩 모델 부적합, 낮은 유사도 임계치 | 근거 문서(Context) 내에 질문에 답할 핵심 내용이 누락됨 | 청킹 크기 조정, 하이브리드 검색 도입, Re-ranking 적용 |
| **생성 실패 (Generation Failure)** | 프롬프트 지시문 모호성, LLM의 추론 및 독해 한계 | 문서에 정답이 명시되어 있으나 답변에서 왜곡 및 환각 발생 | 프롬프트 제약 조건 강화, 시스템 프롬프트 개선, LLM 변경 |
</aside>

### 3.2 환각(Hallucination)과 평가 지표의 관계

<aside>

- **외부 지식 유입에 의한 환각**: 근거 문서에 없는 내용을 LLM 사전 학습 데이터에 의존하여 단정할 때 발생하며, 사실성 점수를 떨어뜨립니다.
- **논리 왜곡에 의한 환각**: 근거 문서의 A조건과 B조건을 혼합하여 잘못된 인과관계로 서술하는 현상입니다.
</aside>

### 3.3 실패 원인 진단 파이프라인 실습

<aside>

검색 결과의 적합성과 생성된 답변의 무결성을 순서대로 점검하여 실패 지점을 판별합니다.

```python
# 진단용 상태 플래그를 정의합니다.
# Context Precision/Recall 분석을 통해 얻은 근거 문서 유효성 여부
has_correct_context = True 

# Faithfulness 평가 결과
is_faithful = False 

# Answer Relevance 평가 결과
is_relevant = True 

# 단계별 조건문을 활용하여 파이프라인의 병목을 진단합니다.
print("=== [RAG 실패 원인 진단 리포트] ===")

if not has_correct_context:
    # 1단계 검색 실패
    print("실패 원인: [검색 파이프라인 실패]")
    print("- 세부 내용: 질문을 해결하는 데 필요한 원본 정보가 검색 결과에 포함되지 않았습니다.")
    print("- 해결 조치: 텍스트 청킹 단위 재설정, BM25 결합 하이브리드 검색, 또는 리랭커 도입 검토.")

elif has_correct_context and not is_faithful:
    # 2단계 생성 실패 (환각)
    print("실패 원인: [생성 파이프라인 실패 - 사실성 결여]")
    print("- 세부 내용: 정답 문서가 주어졌으나 모델이 수치를 변조하거나 환각을 생성했습니다.")
    print("- 해결 조치: 프롬프트에 '문서에 없는 내용은 답변하지 말 것' 제약 추가 및 온도(temperature) 확인.")

elif has_correct_context and not is_relevant:
    # 2단계 생성 실패 (동문서답)
    print("실패 원인: [생성 파이프라인 실패 - 관련성 부족]")
    print("- 세부 내용: 문맥은 충실하나 질문의 요구 사항에 직접적으로 답변하지 않았습니다.")
    print("- 해결 조치: 사용자 질문 형식을 프롬프트 상단에 명시하고 답변 양식 템플릿 지정.")

else:
    # 정상 파이프라인
    print("진단 결과: [통과] 검색과 생성이 모두 정상적으로 작동하고 있습니다.")
```

```
=== [RAG 실패 원인 진단 리포트] ===
실패 원인: [생성 파이프라인 실패 - 사실성 결여]
- 세부 내용: 정답 문서가 주어졌으나 모델이 수치를 변조하거나 환각을 생성했습니다.
- 해결 조치: 프롬프트에 '문서에 없는 내용은 답변하지 말 것' 제약 추가 및 온도(temperature) 확인.
```

### 4.2 개념 요약 키워드

- **사실성 (Faithfulness)**: 출력된 답변이 검색된 문서의 사실 범위를 벗어나지 않았는지 검증하는 척도
- **답변 관련성 (Answer Relevance)**: 답변이 사용자 질문의 의도와 문제 해결 목적에 얼마나 직접 부합하는지 측정하는 척도
- **검색 실패 (Retrieval Failure)**: 문맥(Context) 자체가 누락되어 정답 생성이 원천적으로 불가능한 장애
- **생성 실패 (Generation Failure)**: 유효한 문맥이 주어졌음에도 모델의 독해 한계나 프롬프트 미흡으로 오답이 나오는 장애
- **환각 (Hallucination)**: LLM이 근거가 없는 내용을 사실인 양 그럴듯하게 출력하는 오류

### 4.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **사실성** | Faithfulness | 생성된 답변이 주어진 원본 문서 청크의 내용만으로 엄격하게 뒷받침되는지 나타내는 비율입니다. |
| **답변 관련성** | Answer Relevance | 사용자의 질문 의도를 왜곡하거나 동문서답하지 않고 목적에 알맞게 답했는지 나타내는 척도입니다. |
| **환각** | Hallucination | 언어 모델이 주어진 문맥에 존재하지 않는 사실을 지어내거나 오독하여 출력하는 현상입니다. |
| **검색 실패** | Retrieval Failure | 검색 시스템이 데이터베이스에서 정답 도출에 필요한 문서를 찾아오지 못한 상태입니다. |
| **생성 실패** | Generation Failure | 정답 근거 문서는 정상 확보되었으나, 프롬프트나 LLM 결함으로 최종 답변이 왜곡된 상태입니다. |
