## 2. 검색 실패의 3대 핵심 원인

<aside>
💡

<u>**검색 실패(Retrieval Failure)의 진단 기준**</u>
검색된 문서가 모범 정답을 포괄하지 못하거나(낮은 재현율), 무관한 문서가 상위에 노출(낮은 정밀도)되는 병목 지점을 분류합니다. 

</aside>

### 2.1 청킹 실패 (Chunking Failure)

<aside>

- **발생 원인**: 문서 분할 과정에서 문장이나 표의 문맥이 잘려 정답 정보가 여러 청크로 쪼개진 경우입니다.
- **주요 증상**: 질문과 관련된 키워드는 일부 존재하지만, 완전한 의미 파악이 불가능하여 정답 생성에 기여하지 못합니다.
- **해결 방안**: 청크 크기(Chunk Size)를 확장하거나 청크 간 중첩 구간(Chunk Overlap)을 늘려 문맥 단절을 방지합니다.
</aside>

### 2.2 임베딩 및 어휘 불일치 실패 (Embedding Failure)

<aside>

- **발생 원인**: 질문에 쓰인 표현과 원본 문서 내 어휘의 표현 방식이 달라 벡터 유사도 순위에서 밀려난 경우입니다.
- **주요 증상**: 문서 내에 정확한 정답이 존재함에도 불구하고 상위 검색 결과(`top-k`)에 진입하지 못합니다.
- **해결 방안**: 도메인 특화 임베딩 모델을 사용하거나, 키워드 검색(BM25)과 결합한 하이브리드 검색(Hybrid Search)을 구축합니다.
</aside>

### 2.3 메타데이터 필터링 실패 (Metadata Filtering Failure)

<aside>

- **발생 원인**: 작성 연도, 적용 부서, 문서 분류 등 메타데이터 조건 처리가 누락되거나 잘못 적용된 경우입니다.
- **주요 증상**: 2024년 기준 정보를 물었으나 2022년도 과거 규정 문서가 최상위로 반환됩니다.
- **해결 방안**: 문서 색인 시 메타데이터 추출 규칙을 보강하고, 검색 쿼리에서 필수 속성 필터링을 강제합니다.
</aside>

### 3.1 호환성 처리 및 RAGAS 데이터셋 변환

<aside>

- **라이브러리 호환성 패치**: 일부 패키지 충돌 방지를 위해 가상 모듈을 등록합니다.
- **스키마 표준화**: user_input, reference, retrieved_contexts 표준 키를 적용하여 EvaluationDataset 객체로 변환합니다.

```python
import sys
from types import ModuleType

# 라이브러리 간 import 충돌을 방지하기 위해 가상 모듈을 등록합니다.
dummy_chat_vertex = ModuleType("langchain_community.chat_models.vertexai")
dummy_chat_vertex.ChatVertexAI = type("ChatVertexAI", (), {})
sys.modules["langchain_community.chat_models.vertexai"] = dummy_chat_vertex

dummy_llm_vertex = ModuleType("langchain_community.llms.vertexai")
```

### 3.2 검색 지표 측정 및 심사위원 모델 연동

<aside>

- **모델 연동**: RAGAS 평가 엔진과 호환되는 gpt-4o-mini 모델을 선언하고 전용 래퍼로 포장합니다.
- **지표 클래스 인스턴스화**: LLMContextPrecisionWithReference와 LLMContextRecall 클래스 객체를 생성하여 채점을 수행합니다.

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_openai import OpenAIEmbeddings
from ragas import evaluate
from ragas.metrics import ContextPrecision, ContextRecall
from ragas.llms import LangchainLLMWrapper

load_dotenv()

# 일관되고 객관적인 채점을 위해 temperature=0으로 고정한 gpt-4o-mini 모델을 선언합니다.
judge_model = init_chat_model(
    model="gpt-4o-mini",
    model_provider="openai",
    temperature=0
)

# RAGAS 프레임워크가 인식할 수 있도록 래퍼 클래스로 감쌉니다.
evaluator_llm = LangchainLLMWrapper(judge_model)

metrics = [
    ContextPrecision(llm=evaluator_llm),
    ContextRecall(llm=evaluator_llm)
]

print("검색 평가를 실행합니다. gpt-4o-mini 모델이 정밀도와 재현율을 채점 중입니다...")
evaluation_result = evaluate(
    dataset=ragas_dataset,
    metrics=metrics,
    raise_exceptions=True
)

print("검색 지표 측정이 완료되었습니다.")
```

### 3.3 실패 사례 선별 및 원인 진단 리포트 생성

<aside>

- **실패 사례 추출**: 정밀도 또는 재현율 점수가 0.8 미만인 저품질 검색 건을 선별합니다.
- **원인 분석 체인 실행**: `gpt-4o-mini` 모델을 진단 감사관으로 활용하여 실패 원인과 개선 조치 항목을 작성하고 CSV로 저장합니다.

```python
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 평가 결과를 데이터프레임으로 변환합니다.
df_result = evaluation_result.to_pandas()

# 정밀도 또는 재현율이 0.8 미만인 실패 사례만 선별합니다.
failed_cases = df_result[(df_result['context_precision'] < 0.8) | (df_result['context_recall'] < 0.8)].copy()
print(f"총 {len(df_result)}건 중 {len(failed_cases)}건의 검색 실패 사례가 식별되었습니다.")

# 검색 실패 원인을 청킹, 임베딩, 메타데이터 필터링 관점에서 분석하는 프롬프트를 구성합니다.
diagnosis_prompt = PromptTemplate.from_template(
    """당신은 RAG 검색 품질 문제를 진단하는 전문가 입니다.
    아래의 질문, 모범 정답, 그리고 실제 검색된 문서를 대조하여 검색 실패 원인을 분석하세요.
    
    [질문]: {question}
    [모범 정답]: {reference}
    [검색된 문서]: {contexts}

    다음 3가지 항목에 맞춰 간결하고 담백하게 한국어로 작성하세요:
    1. 실패 유형: [청킹 실패 / 임베딩 실패 / 메타데이터 필터링 실패 중 택1]
    2. 상세 원인: [실패 이유를 2줄 이내로 명확하게 서술]
    3. 품질 개선안: [해결을 위한 파라미터나 구조적 조치 사항 1줄 요약]"""
)

# 원인 진단 체인을 구성합니다.
diagnosis_chain = diagnosis_prompt | judge_model | StrOutputParser()

# 실패 사례에 대해 순차적으로 원인을 진단합니다.
diagnosis_results = []
for _, row in failed_cases.iterrows():
    report = diagnosis_chain.invoke({
        "question": row["user_input"],
        "reference": row["reference"],
        "contexts": "\n".join(row["retrieved_contexts"])
    })
    diagnosis_results.append(report)

# 분석 결과를 데이터프레임에 반영합니다.
failed_cases["diagnosis_report"] = diagnosis_results

# 분석 결과 콘솔 출력
print("\n=== [검색 실패 원인 진단 결과] ===")
for idx, text in enumerate(failed_cases["diagnosis_report"]):
    print(f"\n--- [사례 {idx + 1}] ---\n{text}")

# 최종 리포트를 CSV 파일로 저장합니다.
output_csv = "search_failure_analysis_report.csv"
failed_cases.to_csv(output_csv, index=False, encoding="utf-8-sig")
print(f"\n검색 실패 분석 리포트가 성공적으로 저장되었습니다: '{output_csv}'")
```

```
2. 상세 원인: 질문과 관련된 정보가 포함된 문서가 검색되지 않고, 다른 학기 정보가 검색되어 부정확한 결과가 제공됨.  
3. 파이프라인 개선안: 검색 쿼리의 키워드와 관련된 최신 정보를 우선적으로 필터링하도록 알고리즘을 조정.
```

### 4.2 개념 요약 키워드

- **EvaluationDataset**: RAGAS 프레임워크에서 지원하는 표준화된 평가 데이터 컨테이너 객체입니다.
- **검색 실패 분석 (Retrieval Failure Analysis)**: 정량적 검색 지표가 미달된 사례를 추출하여 청킹, 임베딩, 메타데이터 중 결함이 발생한 지점을 찾아내는 공정입니다.
- **클래스 기반 메트릭 (Class-based Metrics)**: RAGAS에서 각 지표(LLMContextPrecisionWithReference, LLMContextRecall)를 객체 형태로 인스턴스화하고 모델을 주입하여 유연하게 평가를 수행하는 방식입니다.

### 4.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| **평가 데이터셋** | EvaluationDataset | RAGAS에서 다차원 평가를 실행하기 위해 표 형식 데이터를 표준 규격으로 감싼 객체입니다. |
| **청킹 실패** | Chunking Failure | 텍스트 분할 크기나 중첩 설정 미흡으로 인해 핵심 문맥이 경계선에서 단절되는 현상입니다. |
| **임베딩 실패** | Embedding Failure | 질의와 문서 간 어휘 차이로 인해 벡터 유사도가 낮게 책정되어 정답 문서가 누락되는 현상입니다. |
| **메타데이터 필터링 실패** | Metadata Filtering Failure | 기간, 부서 등 데이터의 범주형 속성 조건이 적용되지 않아 불일치하는 문서가 반환되는 현상입니다. |
