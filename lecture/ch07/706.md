## 2. 생성 실패와 환각의 3대 핵심 원인

<aside>
💡

검색기가 정확한 문서를 제공했음에도 LLM이 올바른 답변 생성에 실패하는 결함 지점을 분류합니다.

</aside>

### 2.1 문맥 외 지식 의존 및 환각 (Hallucination)

<aside>

- **발생 원인**: 모델이 제공된 참고 문서보다 자신이 사전에 학습한 기억에 과도하게 의존하여 없는 사실을 지어내는 경우입니다.
- **주요 증상**: 문서에 기재되지 않은 가상의 인물, 날짜, 정책이 사실처럼 정교하게 생성됩니다.
- **해결 방안**: 시스템 프롬프트에 "주어진 참고 문서에 명시된 사실만 근거하여 작성하라"는 엄격한 제약 조건을 설정합니다.
</aside>

### 2.2 문맥 무시 및 정보 누락 (Context Ignored)

<aside>

- **발생 원인**: 제공된 컨텍스트 길이가 길거나 질문과 관련된 핵심 문장이 본문 중간에 묻혀 모델이 이를 읽어내지 못한 경우입니다.
- **주요 증상**: 참고 문서에 명확한 답변이 존재함에도 "제공된 문서에서 관련 정보를 찾을 수 없습니다"라고 답하거나 오답을 반환합니다.
- **해결 방안**: 컨텍스트 압축 기법을 적용해 불필요한 문장을 제거하고, 프롬프트에서 문서의 위치를 질문 바로 위로 재배치합니다.
</aside>

### 2.3 프롬프트 지시 불이행 (Prompt Instruction Failure)

<aside>

- **발생 원인**: 답변 분량 제한, 특정 출력 형식(JSON, 표), 어조 등의 제약 지침이 모호하거나 상호 충돌하는 경우입니다.
- **주요 증상**: "한 문장으로 요약하라"는 요청에 긴 줄글을 작성하거나 지정되지 않은 언어로 답변합니다.
- **해결 방안**: 프롬프트 템플릿의 지시사항을 명확한 번호 매김 형태로 구조화하고 Few-shot 예제를 함께 제공합니다.
</aside>

## 3. LLM 모델 기반 생성 실패 분석 실습

<aside>
💡

의도적 오류 데이터셋을 정의하고, LLM 모델을 진단 심사위원으로 연동하여 원인 리포트를 생성합니다.

</aside>

### 3.1 호환성 처리 및 실패 사례 데이터셋 구성

<aside>

- **라이브러리 호환성 패치**: 패키지 간 임포트 충돌을 방지하기 위해 가상 모듈을 등록합니다.
- **샘플 데이터셋 생성**: 환각, 문맥 무시, 지시 불이행 오류 사례와 정상 생성 사례를 판다스 데이터프레임으로 정의합니다.

```python
import sys
from types import ModuleType

# 제거된 vertexai 모듈을 메모리에 가짜로 등록하여 라이브러리 충돌을 방지합니다.
dummy_chat_vertex = ModuleType("langchain_community.chat_models.vertexai")
dummy_chat_vertex.ChatVertexAI = type("ChatVertexAI", (), {})
sys.modules["langchain_community.chat_models.vertexai"] = dummy_chat_vertex

dummy_llm_vertex = ModuleType("langchain_community.llms.vertexai")
dummy_llm_vertex.VertexAI = type("VertexAI", (), {})
sys.modules["langchain_community.llms.vertexai"] = dummy_llm_vertex

import pandas as pd
from ragas import EvaluationDataset

# 이전 강에서 다룬 도서관 안내 데이터를 바탕으로 질문, 검색 문서, 생성 답변을 정의합니다.
# contexts 항목은 검색기가 찾아온 문서 목록이며, response 항목은 평가 대상이 되는 생성 답변입니다.
eval_raw_data = {
    "user_input": [
        "2026년 공과대학 봄 축제 초청 가수는 누구인가요?",
        "중앙도서관 일일 연체료는 얼마인가요?",
        "학생 식당 운영 시간을 1줄로 요약해 주세요.",
        "기숙사 헬스장 이용 시간은 언제인가요?"
    ],
    "retrieved_contexts": [
        ["2026년 공과대학 봄 축제 공식 초청 가수는 아이유입니다."],
        ["2026학년도부터 개정된 규정에 따라 중앙도서관 도서 연체료는 일일 1,000원으로 적용됩니다."],
        ["학생 식당 조식은 08:00~09:30, 중식은 11:30~13:30, 석식은 17:30~19:00에 운영됩니다."],
        ["기숙사 헬스장은 연중무휴 24시간 자율 개방됩니다."]
    ],
    "response": [
        "2026년 공과대학 축제 초청 가수는 뉴진스와 에스파로 확정되었습니다.",
        "중앙도서관 연체료는 하루당 100원입니다. (과거 규정 반영)",
        "학생 식당 운영 시간에 대해 자세히 안내해 드리겠습니다. 학우분들의 편의를 위해 아침에는 8시부터 9시 반까지 식사가 제공되며, 점심시간에는 11시 반부터 1시 반까지, 저녁 식사는 5시 반부터 7시까지 이용하실 수 있습니다.",
        "기숙사 헬스장은 24시간 자율 개방됩니다."
    ]
}

# 딕셔너리 데이터를 2차원 표 형태의 판다스 DataFrame으로 변환합니다.
df_generation_eval = pd.DataFrame(eval_raw_data)

# DataFrame을 RAGAS 평가 함수 규격에 맞는 Dataset 객체로 변환합니다.
ragas_dataset = EvaluationDataset.from_pandas(df_generation_eval)

print("=== [RAGAS 평가용 데이터셋 변환 완료] ===")
print(ragas_dataset)
```

### 3.2 LLM  심사위원 모델 연동 및 진단 체인 구성

<aside>

- **모델 연동**: 일관되고 객관적인 채점을 위해 `temperature=0`으로 고정한 `gpt-5-mini` 모델을 선언합니다.
- **진단 프롬프트 설계**: 언어 모델이 실패 유형을 3가지 범주 중 하나로 분류하고 명확한 개선안을 제시하도록 프롬프트를 구성합니다.

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_openai import OpenAIEmbeddings
from ragas import evaluate
from ragas.metrics import Faithfulness, ResponseRelevancy
from ragas.llms import LangchainLLMWrapper
from ragas.embeddings import LangchainEmbeddingsWrapper

load_dotenv()

# 일관되고 객관적인 채점을 위해 temperature는 0으로 고정합니다.
judge_model = init_chat_model(
    model="gpt-4o-mini",
    model_provider="openai",
    temperature=0
)

# 답변 관련성 평가 시 문장 유사도 비교를 위한 임베딩 모델을 선언합니다.
embedding_model = OpenAIEmbeddings(model="text-embedding-3-small")

# LangChain 객체를 RAGAS 평가 엔진이 인식할 수 있는 래퍼 클래스로 감쌉니다.
evaluator_llm = LangchainLLMWrapper(judge_model)
evaluator_embeddings = LangchainEmbeddingsWrapper(embedding_model)

# 개별 지표 인스턴스에 LLM 및 임베딩 모델 명시적 전달
metrics = [
    Faithfulness(llm=evaluator_llm),
    ResponseRelevancy(llm=evaluator_llm, embeddings=evaluator_embeddings)
]

print("생성 평가를 실행합니다. gpt-4o-mini 모델이 충실도와 관련성을 채점 중입니다...")

# evaluate 실행 (raise_exceptions=True로 디버깅 가시성 확보)
evaluation_result = evaluate(
    dataset=ragas_dataset,
    metrics=metrics,
    raise_exceptions=True
)

print("생성 지표 측정이 정상적으로 완료되었습니다.")
```

```python
import os
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

judge_model = init_chat_model(
    model="gpt-4o-mini",
    model_provider="openai",
    temperature=0
)

# 생성 실패 원인을 정밀 진단하는 프롬프트 템플릿을 정의합니다.
diagnosis_prompt = PromptTemplate.from_template(
    """당신은 RAG 생성 품질과 환각을 전문적으로 진단하는 전문가 입니다.
    아래의 질문, 참고 문서, 모범 정답, 그리고 실제 생성된 답변을 대조하여 오류를 분석하세요.

    [질문]: {question}
    [참고 문서]: {contexts}
    [실제 생성 답변]: {generated_answer}

    답안이 모범 정답 및 참고 문서와 온전히 부합하면 '오류 없음'으로 판정하고, 결함이 있다면 아래 항목에 맞춰 간결하게 작성하세요:
    1. 판정 결과: [오류 없음 / 환각 / 문맥 무시 / 프롬프트 지시 불이행 중 택1]
    2. 상세 원인: [발생 원인을 2줄 이내로 명확하게 서술]
    3. 프롬프트 및 컨텍스트 개선안: [해결을 위한 프롬프트 수정 규칙 또는 컨텍스트 처리 방안 1줄 요약]"""
)

# 프롬프트, 모델, 문자열 파서를 파이프라인 형태로 연결합니다.
diagnosis_chain = diagnosis_prompt | judge_model | StrOutputParser()
```

### 3.3 실패 사례 진단 실행 및 리포트(CSV) 저장

<aside>

- **배치 진단 실행**: 데이터셋의 각 행을 순회하며 진단 체인을 실행하고 결과를 취합합니다.
- **결과 저장**: 분석 결과를 판다스 데이터프레임에 병합한 뒤 엑셀과 호환되는 UTF-8 BOM CSV 파일로 저장합니다.

```python

df_result = evaluation_result.to_pandas()

failed_cases = df_result[(df_result['faithfulness'] < 0.8) | (df_result['answer_relevancy'] < 0.8)].copy()

print("생성 품질 진단을 시작합니다. LLM 모델이 답변을 심사 중입니다...\n")

# 각 사례별 진단 리포트를 수집할 리스트를 선언합니다.
diagnosis_reports = []

for idx, row in failed_cases.iterrows():
    report = diagnosis_chain.invoke({
        "question": row["user_input"],
        "contexts": "\n\n".join(row["retrieved_contexts"]),
        "generated_answer": row["response"]
    })
    diagnosis_reports.append(report)
    print(f"--- [사례 {idx + 1} 진단 완료] ---")
    print(report)
    print()

# 분석 결과를 데이터프레임의 새로운 컬럼으로 등록합니다.
df_generation_eval["diagnosis_report"] = diagnosis_reports

# 최종 리포트를 CSV 파일로 저장합니다.
output_csv = "generation_failure_analysis_report.csv"
df_generation_eval.to_csv(output_csv, index=False, encoding="utf-8-sig")

print(f"생성 실패 분석 리포트가 성공적으로 저장되었습니다: '{output_csv}'")

```

```
생성 품질 진단을 시작합니다. LLM 모델이 답변을 심사 중입니다...

--- [사례 1 진단 완료] ---
1. 판정 결과: 환각  
2. 상세 원인: 생성된 답변은 참고 문서의 정보와 상충하며, 잘못된 정보를 제공하고 있습니다.  
3. 프롬프트 및 컨텍스트 개선안: 질문에 대한 정확한 정보를 제공하기 위해, 신뢰할 수 있는 출처에서의 확인을 요구하는 프롬프트 수정이 필요합니다.

--- [사례 2 진단 완료] ---
```

### 4.2 개념 요약 키워드

- **생성 실패 진단 (Generation Failure Analysis)**: 검색기가 올바른 문맥을 제공했음에도 LLM이 사실 왜곡, 문맥 무시, 지시 불이행 등의 오류를 범하는 원인을 규명하는 품질 평가 공정입니다.
- **심사위원 LLM (LLM-as-a-Judge)**: 정밀하게 작성된 진단 프롬프트와 LLM 모델을 결합하여 대규모 답변 오류를 정량적·정성적으로 자동 판별하는 기법입니다.
- **환각 억제 프롬프트 (Grounding Prompt)**: 모델이 사전 학습된 지식을 임의로 꺼내지 못하도록 "제공된 문서 외의 내용은 모른다고 답하라"는 규칙을 명시하는 기법입니다.

### 4.3 용어 사전

| **용어** | **영어 표현** | **설명** |
| --- | --- | --- |
| 생성 실패 | Generation Failure | 검색 단계에서 올바른 참고 문서를 획득했음에도 최종 답변 생성 단계에서 발생하는 모든 품질 오류입니다. |
| 환각 | Hallucination | 언어 모델이 주어진 참고 문서에 없는 허위 정보를 사실인 것처럼 꾸며내는 현상입니다. |
| 문맥 무시 | Context Ignored | 제공된 검색 문서에 정답이 포함되어 있음에도 모델이 이를 반영하지 않고 기존 사전 학습 기억으로 답하는 오류입니다. |
| 프롬프트 지시 불이행 | Prompt Instruction Failure | 분량 제한, 특정 출력 형식(표, JSON), 언어 지정 등 프롬프트에 명시된 지침을 모델이 누락하거나 어기는 현상입니다. |
